# Workflow Rules

- Commit after every logical change (fix, feature, refactor, docs update)
- Do not batch multiple unrelated changes into one commit
- Do not wait for the user to ask — commit as soon as the change compiles and is complete
- Follow the project commit convention: `prefix(topic): short description`
- If a change spans multiple files but is one logical unit, commit them together
- Never commit debug artifacts, .env files, or temporary test code
