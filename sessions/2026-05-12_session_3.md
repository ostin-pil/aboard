## Decisions worth remembering

1. **Methodology-first beats content-first.** The strongest concrete
   finding after 5 ensembles is methodological (F4 reversal, spread
   varies by question shape), not substantive. Framing the project
   around interpretive friction is more honest than pitching specific
   claims about democratic backsliding. The about page now leads with
   the methodology and demotes the claim graph to "substrate."
2. **Both readings as tension, not picked.** F4's reversal supports two
   defensible readings (false consensus vs. outlier dominance) with
   different implied levers. The product surfaces both side-by-side as
   the actual output — interpretation cards become a first-class
   pattern. Picking one would be a methodological mistake; the tension
   *is* the product.
3. **Tool vs. demo is an explicit split.** User drew it: tool = `/graph`
   editor/exploration UX (entangled with engine migration); demo =
   public surfaces (landing, claim, dossier, OG cards). Today's polish
   prompt blocks target demo only. Tool polish ships with the React
   Flow migration in a separate session.
4. **Staged drafts beat direct commits for prose-heavy reframes.**
   Advisor catch — for the methodology-first rewrite, draft and commit
   one file at a time rather than batch. User instructed
   "work-without-stopping" after ExitPlanMode, so today's commits
   landed without per-file approval pauses, but the per-file commits
   themselves still give a clean rollback unit.
5. **MCP over skills / Managed Agents / OpenAI Workspace Agents.** The
   filing-process research surfaced four agent-side onboarding paths.
   MCP wins on platform-agnosticism (Anthropic, OpenAI, Google all
   speak it), discoverability (registry + server-card metadata), and
   write-back cleanliness (aboard owns the authorization layer; agents
   never touch `data/` directly). Skills are Claude-only; Managed
   Agents lock to Anthropic; OpenAI surfaces require bilateral
   integrations.
6. **Don't quote unverified MCP specifics.** Advisor catch — the
   research agent's report cited server counts, registry dates, rate
   limits. These aren't verified from primary sources. The qualitative
   case for MCP stands without them; the agent-onboarding doc lands
   without those numbers and the README/CONTRIBUTING follow suit.
7. **React Flow over Cytoscape for engine migration.** Both viable;
   React Flow wins on DX-fit (React-native, Next.js stack), custom
   edge labels (needed for the rationale popover), and built-in
   pan/zoom/drag (the 985-line vanilla engine's three failure modes
   this branch — re-mount loop, node-drag null-ref, hit-zone leakage —
   are exactly the categories React Flow handles by construction).
8. **The hardcoded SEED constant in `public/graph-engine.js` (lines
   18-95) is real tech debt.** Duplicates server data; resets to
   it on user "reset to seed." Engine migration is the right time to
   delete it and load from the API.
