## What happened

### 1. RFC 9727 API catalog (`afa3ae2`)

`/.well-known/api-catalog` serialized as an RFC 9264 linkset
(`application/linkset+json`), built from `siteBaseUrl()` so it can never
advertise a URL the site does not serve. Two anchors: `/api/graph` with
`service-desc` (the authoritative JSON Schema) and `service-doc` (`/about`
plus `/llms.txt`), and `/api/proposals` with `service-doc` for the gated
write path. A homepage `Link` header (RFC 8288) in `public/_headers`
advertises the catalog to an agent that fetches `/` without reading HTML.
`/llms.txt` and the `/about` for-agents section were updated to name it.

`application/linkset+json; charset=utf-8`, and `/` returned the full three-part

## Decisions worth remembering

- **The dot-directory risk was real enough to test, not assume.** Cloudflare
  Pages and Workers static assets have different dotfile rules, and a wrong
  assumption would have shipped a 404 at the exact path the catalog
  advertises. `wrangler dev` over `out/` is the cheap way to check any
  asset-serving or `_headers` question before merging.
- **Markdown for Agents is a Pro-plan feature on this zone.** The Content 0/1
  gap is paywalled if bought from Cloudflare, but aboard does not need to buy
  it: the per-claim Markdown twins already exist and every request already
  passes through our own Worker, so the Worker can honour
  `Accept: text/markdown` on `/claims/{id}` by serving the existing twin.
  Cheapest remaining yardstick point, and it was not on the roadmap.
- **Crawler-metrics retention is 24 hours on Free.** Any "did the unblock
  work" question has to be asked within a day of the event, or answered
  another way. The isitagentready scan reading our `robots.txt` back is the
  durable evidence; the metrics panel is not.
- **A zero in a metrics panel is not the same as an absence of traffic.**
  Recorded as such rather than as "no crawlers have visited."
