## Context

A research session, not a code session. Goal: run a deep, multi-source,
fact-checked study of aboard's competitive/UX/market landscape to **validate
(and adversarially stress-test) the methodology-first thesis** — contested
questions held as falsifiable claims with "both readings as a tension," explicit
cruxes, and agent attribution. Scoped via `AskUserQuestion` to three choices:
benchmark **all four** adjacent categories (forecasting/markets, argument
mapping/debate, knowledge graphs/semantic publishing, AI-agent data/synthesis);
optimise for **AI agents as the primary consumer** (machine-readability, JSON-LD/
MCP, API ergonomics); and treat **thesis validation** as the goal. Executed with
the `deep-research` workflow. The run produced real signal but also a instructive
failure mode worth recording in detail.

## What happened

### 1. Ran the `deep-research` workflow (5 angles, 23 sources, 106 claims)

Decomposed into 5 search angles, fanned out parallel web searches, fetched 23
sources, extracted 106 candidate claims, and targeted the top 25 for adversarial
3-vote verification. Aggregate: **1,051,219 sub-agent tokens, 105 sub-agents,
389 tool calls, ~91 min wall-clock** (5,436,585 ms). ~10k tokens/agent average.

### 2. The verification phase broke structurally after 6 claims

Verification produced real votes for only the **first 6 claims** (all
forecasting/Metaculus). For the remaining ~19, **every verifier agent crashed
without calling `StructuredOutput`** (after 2 in-conversation nudges each) and
was logged as `0-0 (3 abstain)`. An abstain means *not tested*, **not refuted**.
So ~57 of ~75 verify-phase agents produced no usable signal — roughly half of all
agents and a large fraction of the 1.05M tokens were spent on a verification loop
that returned nothing.

### 3. The auto-summary was confidently wrong; advisor + manual re-verify fixed it

Because crashes registered as "abstain," the workflow's default synthesis read
the absence as a finding: "forecasting validated; cruxes / both-readings /
semantic-publishing are the weak, riskiest bets." Taken at face value this would
have **mis-steered aboard's product direction.** An `advisor` call flagged the
false asymmetry before it was enshrined. The four thesis-critical precedents were
then **re-verified by hand** (4 `WebFetch` calls — a rounding error against
1.05M tokens):

- **Wikidata rank** (preferred/normal/deprecated) — a deployed "hold multiple
  values rather than collapse" precedent → supports both-readings-as-tension.
- **AIF** (I/RA/CA/PA nodes, serialized to RDFS *and* JSON) — ~20-year precedent
  for machine-readable argument structure; nuance: precedent without adoption.
- **WordLift schema.org-RAG paper** (arXiv 2603.10700, real) — bare JSON-LD =
  d=0.18 (small); dereferenceable entity pages = +29.6% (d=0.60); agentic
  traversal adds more. The most actionable design signal in the run.
- **Google ClaimReview retirement (June 2025)** — markup value is platform-
  fragile; ~4B impressions/yr vanished. aboard's own-API/MCP path avoids that
  single-platform dependence.

### 4. Wrote the durable artifact

`research/agent-first-validation.md` — a corrected three-bucket verdict
(Validated / Refuted / Found-but-untested-this-run), a four-landscape synthesis
table, and a ranked, agent-first feature list. Honest provenance note about the
verifier failure is in the doc itself.

## Outcomes (substance)

- **Validated (6, primary-sourced):** an agent-first forecasting platform already
  exists with institutional backing (Metaculus AI Benchmarking Tournament, bots
  read + write via API); falsifiability is enforced by centralizing the arbiter
  and banning "X says Y" triggers; LLMs approach but don't beat the crowd (Brier
  .179 vs .149); resolved-claim corpora exist but ~90% need curation.
- **Refuted (3):** no verified cross-platform scoring blueprint; "structured
  argument = verifiable reasoning" and "argument structure is the trust basis"
  (both strong claims in one 2025 preprint).
- **Thesis reframe:** the distinctive bets are **precedented but under-adopted** —
  the risk is *adoption*, not *feasibility*, plus the unsolved **"who resolves a
  contested agent-written claim?"** (every validated platform centralizes that in
  humans). The "riskiest bets" framing was a verifier artifact.
- **Design correction:** JSON-LD-by-default is necessary but not sufficient for
  agents; the leverage is dereferenceable entity pages + agent-navigable links +
  multi-hop traversal.

## Workflow retrospective

### What went right

1. **Scoping before spending.** Three `AskUserQuestion` choices narrowed an
   otherwise unbounded "landscape" question into a sharp, four-axis, agent-first
   study. Worth keeping as a standard pre-step for any open-ended research run.
2. **Search + fetch did their job.** All four axes returned balanced material
   (4 novel debate, 4 novel semantic, 3 novel contrarian, plus forecasting). The
   *descriptive* landscape the user asked for was fully supported; only
   verification broke.
3. **Forecasting findings are genuinely high-confidence** — primary sources
   (Metaculus's own repos/docs + a NeurIPS-2024 paper), real adversarial votes.
4. **The advisor caught the framing trap** before it reached the user or the doc.
5. **Cheap human-in-the-loop verification beat the expensive swarm.** 4 targeted
   fetches recovered the claims that mattered most, for ~0% of the token cost.
6. **The deliverable was made durable** (written to `research/`) before declaring
   done, so the synthesis survives context loss.

### What went wrong

1. **Verifier `StructuredOutput` failures** crashed ~57 of ~75 verify agents.
   The single largest line item of spend produced no signal.
2. **Silent failure masquerading as a finding.** Crashes logged as "abstain"
   fed a confident-but-wrong auto-summary. The failure mode wasn't just wasteful,
   it was *misleading* — the most dangerous kind.
3. **Evidence imbalance baked into the output.** 5 of 6 confirmed claims trace to
   2 source clusters (Metaculus + one arXiv paper). The distinctive-bet claims
   went untested, not disproven — easy to misread as "weak."
4. **Mediocre efficiency.** ~1.05M tokens / 91 min for an estimated 40–50%
   productive yield.
5. **One source (arXiv 2603.10700) looked suspicious** (future-dated id) but
   verified real on fetch — a reminder to spot-check rather than assume.

### How to mitigate the bad / amplify the good

1. **Never treat a workflow's auto-summary as ground truth.** Always reconcile
   `0-0 abstain` (not tested) vs real negative votes (`0-2`/`0-3`) before
   believing any "X is the weak/risky bet" conclusion.
2. **Treat the verify phase as the fragile, expensive link.** Reallocate budget
   toward broad search + a *small* set of targeted, human-checkable verifications
   on the handful of claims that actually move a decision. Front-load claims with
   a single canonical URL (specs, docs) — cheap to check, high value.
3. **Patch the verifier before any re-run.** Resuming via `resumeFromRunId` will
   likely re-hit the same `StructuredOutput` failure; better to edit the
   `deep-research` workflow script's verify stage (more robust schema coercion,
   or text-vote + parse, or fewer-but-sturdier verifiers).
4. **Add an abstain/crash guard.** If >~25% of verifier agents abstain or crash,
   the workflow should emit a loud warning instead of a confident synthesis.
5. **Keep the advisor + manual-fetch reconciliation as a standard closing step**
   for any high-stakes research synthesis — it is cheap insurance against exactly
   this failure.

## Decisions worth remembering

1. **`0-0 abstain` in a deep-research run means "not tested," not "refuted."**
   The verifier crashing is indistinguishable from a real abstention in the log;
   the auto-summary conflates them. Always reconcile manually.
2. **The methodology-first thesis is precedented, not unfounded.** Both-readings
   has a deployed precedent (Wikidata rank); machine-readable argument has AIF.
   The real risk is *adoption* + the *resolution* question, not feasibility.
3. **JSON-LD markup alone is low-leverage for agents** (d=0.18); the win is
   dereferenceable, entity-centric, agent-navigable pages (+29.6%). This should
   shape how aboard publishes claims, not just *that* it publishes JSON-LD.
4. **The agent-first forecasting axis is occupied** (Metaculus AIB). aboard's
   wedge is the cross-module graph + a pre-curated, resolution-rigorous corpus —
   not "agents forecast."
