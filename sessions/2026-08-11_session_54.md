## What happened

Five findings, closed in the order that let each one be verified on its own.

### 1. E9, four unrelated one-liners

The grab-bag, split into three commits because they share a finding number and
nothing else.

Both flashes in `GraphFullbleed.tsx` were fire-and-forget timers. Re-arming
without clearing let the older timer end the newer flash early, so saving twice
inside 1.8 seconds made "saved locally" vanish mid-second-save, and an unmount
with one pending set state on a dead component. `navigator.clipboard` is absent
outright on an insecure origin and `writeText` rejects when the document is not
focused; neither had a rejection path, so the button read "copy to clipboard"
forever and the failure was reported nowhere.

The confidence input trusted `min`/`max`, which are advisory: the browser marks
the field invalid and still reports the typed value, so a typed "5" reached the
graph and failed later in the loader, against a file the editor had already
written.

`useGraphInstance` was a dead graph-engine-era export with no callers anywhere
in `src/`, `worker/`, `mcp-server/` or `clients/`.

### 2. E9's fourth part turned into a real refactor

`loadPersisted` and `clearPersisted` ran inside a render-phase `useMemo`, and
the write was worse than the finding said: besides the three `clearPersisted`
paths, the load pruned the pre-v3 keys on every call. A render React discards
had already deleted the user's sandbox.

`loadPersisted` is now pure and returns a `LoadOutcome` of `ok` / `empty` /
`unusable`; `pruneLegacyStoreKeys` is a separate export; `ClaimGraphRFInner`
does both writes in an effect, where StrictMode's double-invoke is harmless
because both are idempotent. The suite gained the property the split exists for
(the load writes nothing, under four different stored states), and a planted
`removeItem` in the load fails three of those four, the fourth correctly
returning before the planted line.

### 3. E8, minting ids into the wrong namespace

`newId` minted bare `S`/`M`/`L` whatever the target domain, so filing into
`inequality` produced `S4`, colliding with `democratic_backsliding` the moment
an exported PR pack is applied.

The fix reads the prefix off the domain's own claims rather than deriving it
from the domain's name, and falls back to the name's initials only for a domain
with no claims yet. That ordering is what gets `democratic_backsliding` right:
its prefix is the empty string, which no name-derived rule would ever produce.
Uniqueness is still checked against every claim in the graph, because the
prefix is what makes the namespaces disjoint and a mint that assumed
disjointness would be the same bug one level up.

`mint-id.test.ts` closes with a check over the live corpus: for every domain in
`data/`, the derived prefix has to be the prefix that domain's claims actually
use. A future domain adopting a convention the function cannot reproduce fails
there rather than in someone's exported pack.

### 4. E5, shortcuts that ignored edit mode and open editors

Guarded at the instance rather than at the handler, because the toolbar buttons
and the keyboard shortcuts both arrive through `buildInstance()` and only the
keyboard path was ever going to get checked. One wrinkle forced the shape: the
chrome captures the instance once in `onReady` and holds that object for the
lifetime of the page, so a guard closing over `editable` or `editingNode`
directly would have frozen at its mount-time reading. Both are read through refs
the existing mirror effect keeps current.

The toolbar buttons are `disabled` rather than merely inert. A button that
silently does nothing reads as a bug, and the guard should be visible.

### 5. E6, three modals with no dialog semantics

The editors carried `role="dialog"` and nothing else and the JSON-LD modal had
no role at all: no `aria-modal`, no accessible name, no initial focus, no trap,
no Escape. A keyboard user opening the node editor kept focus on the canvas
behind it with no way out but the mouse.

One `ModalDialog` shell now backs all three; each caller keeps its own markup
and classes, and what is shared is the semantics and the focus behaviour. The
callers pass an inline arrow for `onClose`, so the trap is set up once against a
ref rather than depending on that identity, which would otherwise have re-run
the effect on every keystroke and yanked focus back to the first field while the
user typed in the third.

`focus-trap.ts` holds the part that can be quietly wrong: which elements take
focus, and where Tab goes next. It is tested under `jsdom` rather than the
in-memory stub `persist.test.ts` uses, because the thing under test is a CSS
selector and `document.activeElement`, and a hand-rolled fake would only assert
that the fake matches the fake. `jsdom` is a new devDependency and a per-file
`@vitest-environment` docblock, with no config file. Dropping the forward wrap
fails three tests; letting disabled buttons through fails one.

The JSON-LD modal's `#jsonldModal` id became a `.jsonld-modal` class, since the
shell owns the element and takes a class name.

### 6. E7, filing into a collapsed group

The expand path lived only inside `toggleDomainCollapse`, so the chevron ran it
and the node editor ran none of it: a claim filed into a collapsed group landed
visible and detached below the 220x56 pill, drawing edges to siblings that were
hidden.

`expandGroupNodes` and `expandGroupEdges` moved to `engine-to-rf.ts`, where the
collapse geometry already lived, and both callers share them. Expanding rather
than hiding the new claim is a choice: hiding it inside the pill would be
consistent with the chevron, but a save that visibly does nothing is worse than
a view state that changes.

Whether the save expands is decided before the updater runs, against the
committed graph, because a state updater has to stay pure and React may call it
twice. Deciding it inside would have been the same defect this session had just
fixed one commit earlier.

Two things looked like regressions and were not, and both cost time worth
recording.

**The canvas rendered blank in `npm run dev`.** Twenty-eight node elements
existed with real bounding boxes and `visibility: hidden`, no console errors.
Checking out `fc4792b`'s UI files into the worktree reproduced it exactly, which
settled it as environmental before any of it got blamed on the session: the
automated tab reports `document.visibilityState === "hidden"`, never paints, and
React Flow's ResizeObserver never fires, so nothing is ever measured. The built
export in a normally painted tab renders fine.

**The renamed CSS selector appeared not to apply.** The served stylesheet still
carried `#jsonldModal` and lacked the new `:disabled` rule, with `cache:
"reload"` proving it was the server and not the browser. This is the Turbopack
CSS staleness already in `knowledge/issues.md`, provoked by the revert-and-
restore cycle above; the file on disk and the production build were both correct
throughout. Restarting the dev server did not clear it because the `.next` cache
survived. The browser pass ran against `npm run build` output instead, which is
the artifact that ships and the better thing to check anyway.

One real mistake in the middle of that: the first E7 browser run tested a build
made before the E7 commit, and the group did not expand. Rebuilding and
re-running showed the fix working. The build is not a fact about the working
tree unless it was made after it.

## Decisions worth remembering

- **Guard where the state lives, not where the symptom is.** E5 reads as a
  keyboard-handler bug and the fix belongs on the instance, because the toolbar
  buttons take the same path and would have kept the defect. The handler keeps a
  local `editable` check anyway, since a reader of that file should not have to
  find the instance to know the rule.
- **A captured object freezes its closures.** The chrome holds one
  `buildInstance()` result forever, so anything the instance needs to know about
  changing state has to be read through a ref. This is not obvious from either
  file alone and it is why the guards look indirect.
- **Test the thing that can be wrong, in the environment it is wrong in.** The
  focus trap is a CSS selector plus `document.activeElement`. Testing it against
  a hand-built fake would have asserted the fake. One devDependency bought a
  real DOM and made the audit's own axe-core item cheaper.
- **Reproduce on the base commit before believing a regression.** The blank
  canvas looked like this session's doing and was not, and checking out the
  base's files into the same worktree answered it in one step.
- **A build is only evidence about the tree it was built from.** The first E7
  browser check tested a build that predated the fix and reported the bug still
  present.
- **Closing findings in a file makes that file bigger.** `ClaimGraphRF.tsx` went
  from 1139 to 1207 lines. The transform moved out to a pure, tested module, so
  the direction is right, but the split gets more expensive every session that
  defers it.
