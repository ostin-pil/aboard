## What happened

### 1. Reading React Flow before writing anything

`@xyflow/react` 12.10.2, read out of the bundle rather than from
memory, because the whole question is what its wrappers already do.
Four facts decided the design.

`NodeWrapper` renders `tabIndex: isFocusable ? 0 : undefined` and
`role: node.ariaRole ?? "group"`, with `nodesFocusable` defaulting to
true. So the canvas did not lack tab stops. It had one per node and one
per edge already, nameless and inert, which is a worse starting point
than none: a screen reader announced "group" plus the card's run-together
text, and Enter did nothing a user could see.

`node.domAttributes` is spread *after* the built-ins. That is the
supported hook the issue anticipated, and it is also a trap: supplying
an `onKeyDown` there replaces React Flow's own, which handles Enter and
Space for selection, arrows for moving a selected node, and Escape for
unselecting. Taking arrow-key movement away from keyboard users in the
name of keyboard access would have been a poor trade.

`ariaLabel` on the node and edge objects is the only route to naming
the focusable element, since it is the wrapper and not anything a
custom component renders.

`ariaLabelConfig` overrides the `aria-describedby` text. Its node key
is chosen by `disableKeyboardA11y`, and the branch used when keyboard
support is *on* is the one named `keyboardDisabled`. Overriding only
the obvious key would have left every real reader on React Flow's
default text, which is why there is a test for that specific mistake.

### 2. The keyboard model

Focus mirrors hover; Enter mirrors click. That fell out of the existing
pointer semantics rather than being invented, and it is what makes the
two input paths one code path instead of two that drift.

Focusing a node lights its neighbourhood, exactly as hovering does.
Enter opens the detail popover, which takes focus, because it renders
after every node and edge on the canvas: left where it is, its "open
detail" link sits thirty tab stops from the node that opened it.
Escape closes it and hands focus back.

Focusing an edge opens its rationale, the same panel hover opens. Enter
opens the edge editor when the canvas is editable, and when it is not,
moves focus into the panel so its source links are reachable. The
panel gained `onFocus`/`onBlur` mapped to the same cancel and schedule
its mouse handlers use, without which moving into it blurs the edge and
closes the panel under the focus that just arrived.

Enter alone, not Space. Space is React Flow's `panActivationKeyCode`
and half of its selection keys, and a third meaning for it would have
been a conflict for no gain.

### 3. Where the handlers went, and the two disables

Off the components entirely. Node clicks and hovers now arrive through
React Flow's `onNodeClick`, `onNodeMouseEnter` and `onNodeMouseLeave`,
and keyboard and focus through one `keydown`/`focusin`/`focusout`
listener on the canvas root. Native listeners rather than JSX props,
because the root is not an interactive element and should not claim to
be; the events it handles belong to the nodes and edges inside it.

That is also what retires the two `eslint-disable` comments honestly.
The rules fire on a static div that binds `onClick` with no keyboard
equivalent, and the answer is not to add a handler beside the click
(which would give every node a second tab stop, and never fire anyway)
but to stop binding interactions on the div. `ClaimNode` is now purely
presentational. `ClaimEdge`'s label became a real `<button>` held out
of the tab order with `tabIndex={-1}`, since the edge's own wrapper is
already a stop and the label is a pointer affordance for the same
action.

`GraphContext` lost `setFocusId` and `openNodePopover` with them. Both
existed only so the components could reach state that now has no
component-side caller.

Two guards the model needs, both tested. `isNativeActivationTarget`
declines Enter when the browser is about to activate a button or link
of its own, without which Enter on a node's edit button opens the
editor *and* the detail popover. And `resolveCanvasTarget` checks the
edge label separately from the edge, because `EdgeLabelRenderer`
portals the label into a sibling container, so `closest` from it never
reaches the `<g>` it belongs to.

### 4. Names for the tab stops

`aria-labels.ts` builds them. A node reads as "symptom S1: Liberal
Democracy Index in global decline, confidence 0.90, 1 forecast", which
is the card's kind, id, confidence and badges in words rather than as
`c=0.90` spelled out a character at a time. An edge reads as the
relation it asserts, using canonical endpoints so an edge re-pointed at
a collapsed group's pill still names the claims it joins rather than
`__domain_inequality`.

Applied on the way into React Flow rather than baked in at `engineToRF`,
which matters for two reasons. The node editor, the bulk actions and
the domain filter all rewrite node data, and only one of them would
have remembered to rewrite a label too. And `nodesRef` is what the
exporter and the persisted sandbox read, so a label baked into the
state would have ended up in localStorage and in the PR pack.

### 5. What the browser pass changed

Two things, both invisible to every command in the gate, both found by
driving the built output rather than `npm run dev`.

The edge focus ring rendered nothing. `.react-flow__edge-path` takes
its `stroke-width` from an inline style in `ClaimEdge`, per kind, and
an inline style beats any selector; the rule needed `!important`. A
focus ring that silently does nothing is well-typed, lints clean and
passes every test.

The edge description promised "Escape to dismiss", and it does not.
Escape closes the rationale, and the focus still sitting on the edge
re-opens it in the same frame, so the panel never visibly goes away.
Moving focus away is what dismisses it. The text now says that, and a
test asserts the word "dismiss" is absent from both edge descriptions,
with the reason written above it.

Everything else was confirmed rather than corrected: Enter opening the
node popover with focus and Escape returning it to the wrapper, Enter
on an edge opening the editor for `M2 -> S2`, Enter on a node's edit
button opening only the editor, the read-only inline graph moving focus
into the rationale panel and back, and the dashed node ring at
`rgb(245,245,244) dashed 2px`.

Two automation traps cost time and are now written into `CLAUDE.md`
beside session 55's `requestAnimationFrame` one. `document.hasFocus()`
is false whenever the window is not frontmost, and `element.focus()`
then moves `activeElement` while firing no `focusin` at all, so the
canvas looks completely inert and the first two probes said the feature
did not work. And a mouse pointer left parked on the canvas keeps
firing `mouseleave` into the same `focusId` the keyboard is setting,
which reads as the highlight being broken. Both were misread as bugs
before being identified.

### 6. The remainder: tab order

Measured, not inferred. Tab into the fullbleed canvas and the first 26
stops are edges; the 28 claims come after all of them. React Flow
renders `.react-flow__edges` before `.react-flow__nodes` because edges
paint under nodes, and tab order follows the DOM.

Both levers cost more than they save. `edgesFocusable={false}` deletes
the edges' keyboard path entirely, and since focus is what opens a
rationale, that is the whole feature for edges. A positive `tabIndex`
is what `jsx-a11y/tabindex-no-positive` exists to refuse. Filed as its
own dated entry with the measurement and the two things that would
change the answer.

## Decisions worth remembering

- **The tab stops already existed.** The issue read as "the canvas has
  no keyboard path", and the truer statement is that it had seventy of
  them, unnamed and inert. That reframing is what made naming half the
  work rather than an afterthought, and it is only visible by reading
  React Flow's wrapper rather than the components.
- **A spread-last extension point is a replacement, not an addition.**
  `node.domAttributes` looks like the API for this and would have
  silently removed arrow-key node movement. Listening on an ancestor
  adds to React Flow's handler instead of standing in for it.
- **Removing a handler is a better answer to an a11y lint than adding
  one.** Both disables came off because the divs stopped binding
  interactions, not because a keydown was bolted on beside the click.
  The rule was pointing at the design, which is what it is for.
- **A focus ring is a claim the test suite cannot check.** `:focus-visible`
  does not match a programmatic `.focus()`, and a rule that loses to an
  inline style renders nothing while every command in the gate stays
  green. The browser pass earned its place on this one line.
- **Describe what the keystroke does, not what it should do.** Escape on
  an edge really does close the rationale, and focus really does re-open
  it in the same frame. Promising a dismissal that visibly does nothing
  is worse than promising nothing, so the description lost the sentence
  and gained a test.
- **An automation artifact reads exactly like a broken feature.** Three
  separate readings said the canvas was inert; all three were
  `document.hasFocus()` being false. Session 55 wrote its equivalent
  down for the same reason, and that note is what made this one
  recognizable rather than a debugging session.
