### 3. Batch 1, canonical URLs (PR #50)

The only findings that were live production defects.

- **A1:** no `metadataBase`, so under `output: "export"` every file-convention
  OG image resolved against `http://localhost:3000`, giving 126 URLs across 32
  of 33 built pages. Every social unfurl in production was broken. `SITE_URL`
  did not cover it, since that feeds JSON-LD `@id`s only.
- **A2:** a dead `aboard.dev` domain in the two OG card generators and the
  client "Copy JSON-LD" export, so the two published representations disagreed
  on identity IRIs.

Fixed by adding `metadataBase`, extracting `src/lib/vocab.ts` as the single
stable vocabulary (imported by both the API serializers and the client export
so they cannot drift apart again), and deriving display hosts from
`siteBaseUrl()` via a new `siteHost()`. Verified in the built output: 126 to 0.

Two gates landed with the fix, at two altitudes, because both halves of the
defect were invisible to every existing check. The URLs are computed by Next at
build time, so `tsc` cannot see them, and they live in `<meta>` tags, so the
schema validator cannot either. `src/lib/canonical-urls.test.ts` runs under
`npm test`; `scripts/check-built-urls.mjs` asserts over the built HTML in CI.

The client export's document *shape* (`filedBy`/`relations`) still does not
conform to `v0.json`. That was left deliberately and noted in a comment at the
site, since A2 asked for agreeing identity IRIs, which is done.

### 4. Prose gate wired (PR #51)

Prompted by a question about whether prose-mint was in use on PR bodies. It was
not: installed, but with no config, no CI step, no manifest wiring, and none of
this session's PR bodies scanned.

The manifest already had the hook (`prose_gate` and `prose_rule`, both `none`),
so this filled it in rather than inventing a mechanism. `bin/check-prose.sh`
forwards its arguments to `prose-mint scan`, matching the shape session-end
already calls. `plans/` and `sessions/` carry per-directory `.prose-mint.toml`
files disabling the `hard-wrap` category, since hard wrapping at roughly 76
columns is house style in both trees and the detector was flagging the
convention itself (19 of 30 hits on `agent-surface.md`).

## Decisions worth remembering

- **Verify an audit before acting on it.** Four of nine severities were
  overstated and one "missing" gate already existed. The re-audit cost far less
  than implementing fixes against wrong premises would have, and it found the
  session's most serious bug (E1) in ground the first pass never covered.
- **A gate must be verified in both directions.** `check-built-urls.mjs` was
  tested against a fixture reintroducing the defect (exit 1) as well as the real
  build (exit 0). An earlier, blunter version flagged the `/about` page's
  visible "validate against your dev server" instruction, which is why the check
  now matches only quote-prefixed URLs. A gate that has never failed is not
  known to work.
- **Scope a gate to the altitude where the defect is visible.** A source-level
  localhost ban produced false positives on legitimate developer instructions,
  while the same invariant expressed over built HTML is precise. Two checks, two
  altitudes, neither doing the other's job.
- **A style gate should fail open, not closed.** `check-prose.sh` exits 0 with a
  loud warning when prose-mint is missing, because the caller treats non-zero as
  "findings to rewrite" and would otherwise loop forever.
- **Control-test a linter before believing it.** prose-mint flagged 195 hits in
  the new audit doc; scanning two untouched existing plans showed the same
  profile, proving `hard-wrap` was flagging house style rather than a new
  defect. Config discovery also failed silently when files were scanned from a
  scratchpad copy instead of in place. The gate then caught 26 em dashes in the
  first draft of this very log, against 6 in session 23's, which is a real tic
  rather than a false positive.
