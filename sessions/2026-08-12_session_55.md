## What happened

1207 lines to 640. Six commits, each one extraction, each verified on its own
before the next.

### 1. The two lists that had to agree

`ARROWHEAD` in `ClaimEdge.tsx` decided whether an edge asked for
`url(#ag-rf-ah-<kind>)`; `ClaimGraphRF.tsx` hard-coded three `<marker>`
elements. A kind set true in the first without a marker in the second asks for
an id that does not exist, and SVG draws that as no arrowhead rather than as an
error. `EdgeMarkers.tsx` holds the table and derives the markers from it.

### 2. Collapse, joining expand

Session 54 moved `expandGroupNodes` and `expandGroupEdges` into
`engine-to-rf.ts` because a second caller needed them, and left collapse inline
in `toggleDomainCollapse`. One direction of the same geometry was reachable
from a test and the other was not. The pair is tested through a round trip now:
what collapse stashes in `collapsedRemap` is exactly what expand restores, and
neither half proves that alone.

### 3. `graph-ops.ts`, which is where the arithmetic was

Seven functions, previously the bodies of `setNodes`/`setEdges` updaters:
`resolveExpandTarget`, `saveClaimNode`, `groupClaimsInto`, `moveClaimsToRow`,
`applyXPositions`, and the two domain-flag passes with `claimsInDomain`.

This is the part of the file that can be quietly wrong. Slot columns,
reparenting, the conversion between a grouped child's local coordinates and
absolute ones, and the rule that an edge is in the domain only if both of its
endpoints are. None of it was reachable without rendering the canvas.

A React state updater has to stay pure and may be invoked twice. That was
previously a matter of discipline, and session 54 had to fix a case where it
had lapsed. It is now a property of the type.

### 4. The undo stack as data

`history.ts` holds the stack, `use-graph-history.ts` binds it to React Flow.
The split falls where the reasons differ. Whether a redo tail survives an edit,
and whether an entry aliases objects React Flow will mutate, are questions
about a data structure. Re-measuring a restored group so its collapsed pill
stays draggable is a question about React Flow.

One deliberate behaviour change. The mount snapshot and `instance.reset` both
used to store the same arrays they handed to React Flow, which mutates the node
objects it renders, so the oldest undo step could be rewritten by the present.
Both store copies now, which is what every other entry already did.

### 5. Two hooks, and the nine repetitions that made them cheap

`use-graph-editing.ts` owns the two editor modals and their save and delete
paths; `use-bulk-actions.ts` owns the multi-select toolbar.

What made both cheap was noticing first that
`requestAnimationFrame(() => { snapshot(); persist(); onPersist?.(buildInstance()); })`
appeared nine times. Nine handlers each carried four dependencies for it and
nothing else. One `commit`, plus a deferred variant taking the id of a group
that needs re-measuring, and every one of those dependency arrays collapses to
a single entry. Extracting the hooks without doing that first would have meant
threading four values into each.

Collapsing a group kept its own bookkeeping rather than calling `commit`,
because it deliberately does not notify the chrome: `onPersist` flashes "saved
locally" and re-counts the graph, and a chevron is a view state. That was
already true and read as an oversight until it was written down.

### 6. `seed.ts`, six branches that had each been a bug

Which graph the canvas mounts with lived in a `useMemo`. The landing page once
showed a visitor's editor sandbox; a snapshot predating multi-domain once
rehydrated into an inert graph with no groups; clearing storage on a visitor
who has never edited is a write on every mount. `resolveSeed` takes the load
outcome rather than reading storage, so all six branches are reachable from a
test without a DOM.

## Two environment findings, one of them a false alarm avoided

**Nothing commits in an automated tab.** Session 54 recorded that such a tab
reports `document.visibilityState === "hidden"` and never paints, so React
Flow never measures and no node is rendered. The consequence it did not reach
is worse: `requestAnimationFrame` never fires either, and every commit path
defers to rAF, so a save closed its modal and wrote nothing. Patching
`window.requestAnimationFrame` to a timer in the console is enough, and it
patches the environment rather than the app. The checks above all ran that way.

**`reset` freezes the renderer outright.** It reproduced with the patch removed,
so the patch was not the cause. Rather than guess, main's graph directory was
checked out into this worktree, rebuilt and clicked: it freezes identically on
`75bf36b`. Pre-existing and environmental, not this session's, and the one row
missing from the table above. Whether a painting tab is affected is unknown and
was not established either way.

One pre-existing quirk observed and deliberately preserved: undo and redo do
not refresh the chrome's node count, because `restore` persists without calling
`onPersist`. The counts read 26n while the sandbox held 25 claims. Changing it
inside a refactor would have been a behaviour change smuggled in as tidying.

## Decisions worth remembering

- **Find the repetition before extracting the hook.** The nine copies of the
  post-mutation bookkeeping were why every handler carried four dependencies.
  Collapsing them to one `commit` first meant the two hooks needed one value
  each instead of four, and the extraction stopped being plumbing.
- **Split where the reasons differ, not where the lines are.** The undo stack
  divides into a data structure and a React Flow re-measure because those fail
  differently and are debugged differently. That is a better cut than any
  line count would have suggested.
- **A guard with no failing test is a guard with no test.** `groupClaimsInto`
  survived its fault because every case had the selection outside the group.
  Planting the fault is what exposed the gap; the tests alone looked thorough.
- **Reproduce on the base before believing a regression, again.** `reset`
  freezing looked like this session's doing until main's files were built in
  the same worktree and froze the same way. Session 54 learned this and it paid
  for itself immediately.
- **Preserve the quirk, record it.** Undo not refreshing the chrome's count is
  wrong, and fixing it inside a refactor would have made the diff a behaviour
  change nobody reviewed as one.
- **A behaviour change in a refactor is allowed if it is argued.** The history
  copies at mount and reset are a real change, made because the alternative was
  keeping a latent aliasing bug for symmetry with the bug.
