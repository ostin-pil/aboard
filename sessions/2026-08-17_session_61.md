### 2. P2, the guard that replaced Zod

`persist.ts` validates the persisted sandbox with a hand-written guard
over the identical structure the schema checked. Zod was in the client
bundle solely for this — the largest single chunk on the homepage,
materialized twice across the export. Twenty-four new test vectors pin

guard and watching exactly the five position vectors fail. Two argued
behaviour deltas, both pinned by tests: positions must now be finite

extra keys survive where Zod stripped them, so a newer build's field
does not brick an older build's sandbox.

is written; reload, the guard accepts its own output and the position
survives; corrupt the store with a reject vector, the load drops it and
the canonical seed renders with no console errors.

### 4. U6, answered by reading one line

The reset-freeze question dissolved rather than resolved: `reset`
freezes no tab. The toolbar handler opens a native `confirm()`
(`GraphFullbleed.tsx:104`); an automated tab can neither display nor
answer a native dialog, so the renderer blocks on it forever — the very
click that opens it times out at the CDP layer, and every later
evaluate hangs, which is exactly the "freezes outright" session 55
recorded. With `window.confirm` stubbed to true in the same hidden tab,
the full reset path completes: store cleared, history reset, all 28
nodes re-rendered, heartbeat interval still advancing. Filed in
`knowledge/issues.md` as an automation gotcha, not a user-facing bug.

Two measured refinements to the session-55 record, same file: an
automated hidden tab does render nodes today (screenshot capture forces
composition), and timers are throttled to roughly one per second, so
the documented rAF patch drives commits slowly rather than not at all —
a node drag persisted within three seconds under it.

## Decisions worth remembering

- **The guard's two deliberate deltas are written next to it.** Finite
  positions are stricter than `z.number()` on purpose; preserved extra
  keys are looser on purpose (forward compatibility for an older build
  reading a newer build's sandbox). Both argued in the module comment so
  neither gets "fixed" back.
- **The debounce is setTimeout, not rAF, and the comment says why.** The
  repo's own automation caveat is that hidden tabs never fire rAF; a
  rAF-based debounce would be a new path that silently does nothing
  there.
- **Faults were planted before fixes were believed.** The guard was
  weakened and the exact five position vectors failed; continues the
  practice from sessions 45 through 59.
- **Automated tabs must stub `confirm` before clicking controls that
  open native dialogs.** A native dialog blocks the renderer outright
  and an automated tab has no way to answer it; this was the entire
  reset-freeze mystery.
- **A blocked command goes to the operator, not to a peer session.**
  The permission mode blocked `git rebase`; asking session 60 to run it
  would have laundered a denied action through a session with different
  permissions. The operator ran the one line directly.
- **Plan-tracker edits wait for the rebase when a parallel session
  touched the tracker.** Editing `plans/audit-2026-08.md` before
  rebasing would have conflicted with chunk 4's DONE marks for no
  benefit.
