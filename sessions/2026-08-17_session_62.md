## Decisions worth remembering

- **Presence is not validity.** The first pass credited the signing-key
  migration because the keychain entry existed; the entry is an
  8-character stub. An operator step involving a secret is verified by
  a shape or length check, never by the container existing.
- **Read the newest session log before crediting operator steps.**
  Session 61 had already measured the stub. The contradiction only
  surfaced because session-end re-read that log; the verification pass
  should have started there.
- **The tracker rule is now written where sessions will read it:** a
  session taking a chunk strikes its rows in `plans/audit-2026-08.md`
  in the same PR. Three of four chunk sessions did this unprompted; the
  one that did not cost a four-day drift on the drift tracker.
- **Verification passes get recorded in the document they verify,**
  dated, including what the pass itself got wrong (the key
  over-credit). An audit doc that only ever accretes closures reads as
  more certain than it is.
