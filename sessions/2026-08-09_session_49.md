## What happened

### 1. Three pieces propping each other up

`SUPPORTED_EDGE_KINDS` at `engine-adapter.ts:15` was a hand-copy of a four-value
enum containing three values. The filter at `:68` removed what it did not name,
and the cast at `:76`, `e.kind as EngineEdge["kind"]`, was type-sound only
because the filter had already deleted the case the narrower type could not
describe. Remove any one piece and the other two look wrong; leave all three and
every one of them looks locally reasonable.

That is why the finding survived three audits. It is also why the fix is not
"add the missing string in four places": doing that would have restored the same
arrangement with a fourth value in it.

### 2. A one-line file header changed the shape of the fix

`src/types/global.d.ts` opens with `export {}`, which makes it a module, which
means it can carry imports. Ambient declaration files usually cannot, and the
plan's remedy (derive all four sites from `EdgeKind.options`) assumed that
constraint.

Because it is a module, `EngineEdge["kind"]` could become `EdgeKind` itself
rather than a union that has to be kept equal to it. Everything downstream then
follows from the type instead of from a copy:

| Site | Before | After |
| --- | --- | --- |
| `global.d.ts` | 3-value union | `EdgeKind` |
| `engine-adapter.ts` | filter plus cast | neither; nothing left to filter |
| `ClaimEdge.tsx` | 3-key `STROKE`/`DASH` | exhaustive `Record<EdgeKind, …>` |
| `EdgeEditorModal.tsx` | 3 literal `<option>`s | mapped from a label `Record` |
| `exporter.ts` | re-typed claim-kind union | `Record<EngineNode["kind"], ClaimKind>` |

The `Record`s are the enforcement. They are not lookups with a fallback,
deliberately: a fallback would render an unknown kind as a default nobody
notices, which is the failure mode being fixed.

Verified rather than asserted. Adding a fifth kind (`refutes`) to the canonical
enum fails `tsc` with exit 2 at exactly two files, `ClaimEdge.tsx` and
`EdgeEditorModal.tsx`, and nowhere else. Tree restored, exit 0.

### 3. The adapter had no test surface at all

There was no `engine-adapter.test.ts`. This is the same structural reason
session 47 recorded for A6, one module over: code that nothing can reach is code
no gate can see, and the fix has to start by making it reachable. The adapter
was already exported and pure, so here it only needed a test file.

Four tests, and they were watched fail. Restoring the old filter fails three of
them; the fourth, which asserts an edge is dropped when its endpoints fall
outside the selected domain, keeps passing. That is the result to want: removing
the kind filter must not have widened the endpoint filter, and a test that went
red in both directions would not have distinguished the two.

### 4. The enum-sync test covers only what the compiler cannot

The audit asked for a test asserting `EdgeKind.options` against every hand-copy,
all nine or more sites. That was written for a world where the in-repo sites
were literals. After section 2 they are not, so `src/lib/enum-sync.test.ts`
covers only the copies no command in the gate can type-check:

- `mcp-server/src/tools/write.ts` and `mcp-server/src/types.ts`
- `clients/briefing.ts`
- the claim-kind list in `src/lib/mcp/tools.ts`'s tool description, which is
  prose an agent reads as the contract

Both packages are excluded from the root tsconfig, so nothing else reads them.
Asserting the in-repo sites as well would restate what `tsc` proves, and a test
that duplicates the compiler is ceremony that still needs maintaining.

Watched fail against the exact drift being guarded against: deleting `evidences`
from the mcp-server enum and the client union fails precisely those two tests
and no others.

### 5. What `evidences` looks like

It needed ink, since it had never been rendered. `--edge-evidences` is indigo
(`#4338ca` light, `#a5b4fc` dark), added to all three palette blocks including
the `prefers-color-scheme` one, plus the edge-label and popover rules. The dash
is `1 3`, dotted, distinct from solid `causes`, `3 3` `moderates` and `4 3`
`reduces`. It carries an arrowhead, with a marker def to match, because it is
directional; `moderates` remains the only headless kind, and that is now stated
in an `ARROWHEAD` record rather than implied by a two-term condition.

### 6. Fixed in code, unproven in data

`grep evidences data/` is still empty. Adding an edge would mean inventing a
relation and sourcing it, which is content rather than a code fix, so the repair
is proven by test and not by live data. `research/schema.md` called the value
"reserved", which was accurate about the seed and misleading about the
capability; both that row and the compatibility table now say it is supported
end to end and unused, a data gap rather than a capability one.

`public/schema/v0.json` needed no change: it has listed all four kinds since it
was written. The drift was entirely on the front end, below the published
contract, which is exactly where nothing was watching.

## Decisions worth remembering

- **A hand-copy, a filter and a cast can hold each other upright.** Each of the
  three was locally defensible, and together they deleted data. When a finding
  survives more than one audit, look for the arrangement rather than the line.
- **Check what a file is before accepting the constraint it seems to carry.**
  `global.d.ts` looked like an ambient declaration file that could not import.
  Its first line said otherwise, and that turned four coordinated edits into one
  type change the compiler propagates.
- **Prefer the compiler where it reaches, and scope tests to where it does
  not.** The enum-sync test is smaller than the audit specified because most of
  its intended surface is now enforced at build time. A test that restates the
  compiler costs maintenance and buys nothing.
- **Exhaustive records over lookups with a fallback.** A fallback turns a new
  enum member into a silently mis-rendered edge; a `Record` turns it into a
  build failure naming the file.
- **A test that fails in every direction has not been aimed.** The endpoint
  filter test passing while the three kind tests failed is what showed the fix
  narrowed only the intended behaviour.
