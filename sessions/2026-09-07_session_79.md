### 5. `glama.json`, and the distinction it is easy to lose

Its own checklist item, and repository work rather than browser work, so
it landed here: three lines at the repository root naming `ostin-pil` as
maintainer, validated once against the published
`https://glama.ai/mcp/schemas/server.json` with the ajv already in the
tree.

It is a different object from `public/.well-known/glama.json`, which
session 72 published, and the two are easy to conflate because they share
a filename. The well-known file is the **connector** ownership claim and
carries maintainer objects keyed by email against `connector.json`. The
root file is **server** metadata against `server.json` and carries bare
GitHub usernames. This is the same connector-versus-server split the plan
already records at the level of listings, reappearing at the level of
files.

The organisation-owned-repository route Glama documents for `glama.json`
is not what makes the claim work here: `ostin-pil/aboard` is personally
owned, so the claim is a GitHub authentication and the file is a scoring
item only.

## Decisions worth remembering

- **A runbook records the world when it was written.** This one was
  correct on 2026-08-29 and had three of its five steps overtaken by a
  crawler nine days later. Staleness is unavoidable and is not the failure
  mode here. Running the steps without first checking whether their premise
  still holds is. Two `curl` calls settled it before any browser opened.
- **`glama.json` twice means two different things.** Root is the server,
  `.well-known` is the connector, different schemas, different shapes.
  The plan already argued the connector-versus-server split for listings;
  it applies to the files too.
- **The Glama score is gated on a release, not on introspection.** The
  maintainer's stated bar and his platform's checklist disagree, so
  "passes checks" and "has a score" are separate conditions and only the
  first is met.
- **Account authentication stays with the operator.** The claim needs a
  Glama sign-in with the owning GitHub account. That is not something to
  work around, and the session stopped there by design rather than
  treating it as a blocker to route past.
- **A reply that answers half the ask waits.** The maintainer asked for
  the claim and the badge. The badge is done and the claim is not, so the
  comment on #12962 is deliberately unwritten rather than posted as a
  partial answer.
