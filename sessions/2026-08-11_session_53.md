## What happened

### 1. The measurement

Same method as sessions 45, 46 and 48: plant the fault, run the gate, record
what fires. A YAML syntax error in `.github/workflows/ci.yml` and a JSON syntax
error in `wrangler.jsonc`, planted at the same time. All nine gate commands
exit 0.

The interesting part is the asymmetry underneath that, which the audit's framing
did not have:

| File | Reader before this session | How it fails |
| --- | --- | --- |
| `wrangler.jsonc` | CI's `wrangler deploy --dry-run` (exit 1, measured) | CI turns red |
| `.github/workflows/ci.yml` | none, anywhere | CI goes quiet |

A workflow that will not parse does not run. So a broken `ci.yml` presents as a
PR with nothing to report rather than a PR with a failure, and it cannot be
gated from inside itself: the file that would catch the fault is the file with
the fault. That is the whole argument for a local reader, and it is stronger
than the argument for the `wrangler.jsonc` half.

Session 48's measurement of the dry-run still holds where it was made. It exits
0 on an unknown compatibility flag and on a `node:` import with no
`nodejs_compat`. What it does catch is syntax and a stale `main` path.

### 2. A third gap, found by the same probe

`code_globs` had no `*.yaml` either, and that one was never a config question.
Everything under `data/` is `*.yaml`, so a session that edits only a forecast
matched no glob, classified as docs, and skipped the build. The build is the
data gate: the Zod loader plus the referential-integrity checks.

Probe: `probability: 1.7` on `F1.yaml`. `npm run build` rejects it naming the
file and the field (`predictions.0.probability: Too big`), and the session gate
would never have run it. Committed separately from the config work, because it
is a different finding that happens to live on the same manifest line.

### 3. What the reader does beyond parsing

`npm run check:config` parses both files, which is the hole as stated. Two more
rules came out of reading them, both written down in the repo already and both
left to memory:

- **Gate/CI parity.** `CLAUDE.md` has told readers to "read them against each
  other whenever either changes" since session 48. Now every `build_commands`
  entry names the CI step covering it, and every CI step is either one of those
  or listed in `CI_ONLY` with a reason. The two sub-package type-checks cannot
  match verbatim (the gate self-provisions `node_modules`, CI starts from a bare
  checkout), so those declare an `equivalent` instead of asserting a string
  match that was never true.
- **The rate-limit mirror.** `worker/index.ts` declares `RATE_LIMIT_PERIOD_S =
  60` with a comment saying it mirrors `PROPOSAL_LIMITER`'s period in
  `wrangler.jsonc`, and `wrangler.jsonc` carries the comment pointing back.
  Cloudflare accepts only 10 or 60 for that period, so the one legal edit is
  also the one that makes `retry-after` lie to every rate-limited caller, with
  tsc, the tests and the dry-run all staying green.

Structured the way `lint-resolution.ts` is: pure rules in `src/lib/config-lint.ts`
with unit tests, filesystem half and the project-specific tables in
`scripts/check-config.ts`. The JSONC comment stripper is hand-written rather
than depended on, because `strip-json-comments` is in the tree only as a
transitive dependency and `wrangler.jsonc`'s comments contain URLs that a naive
regex truncates at the scheme.

## Decisions worth remembering

- **A file that disables the check cannot be gated from inside itself.** A
  broken `ci.yml` does not fail CI, it removes CI. Any config that gates other
  checks needs a reader that is not downstream of it.
- **Measure the shape before accepting the framing.** The audit called this one
  gap. It was three, they failed differently, and the `*.yaml` one had nothing
  to do with config: a data-only session was skipping the data gate.
- **A comment saying "these two must agree" is a to-do, not a control.** Both
  cross-file rules this session enforces were already written down on both
  sides. Writing it down twice is what made them look handled.
- **Declare the equivalence rather than assert a false match.** The two
  sub-package type-checks genuinely differ between gate and CI. A parity check
  that pretended otherwise would have had to be weakened until it caught
  nothing.
- **A test that fails may be a wrong fixture.** Both first-run failures were the
  test's fault, and the code's second finding was correct each time.
