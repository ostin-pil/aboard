## What happened

### 1. The schema test, and the hole it closes

`public/schema/v0.json` is the published contract, and nothing in `npm test`
checked the serializers against it. The only enforcement was
`clients/validate.ts` in CI, which needs a built export and a running server, so
drift surfaced at the last CI step as an Ajv error far from its cause. Sessions
47, 48 and 49 each had to run that check by hand.

`src/lib/jsonld.test.ts` asserts two things over a fixture exercising every
claim kind, all four edge kinds, resolved and unresolved forecasts, a dossier
with cruxes, an analysis, and both a fully-populated and a bare `Source`:

1. the fixture is valid *input* under the Zod schemas in `types.ts`
2. what the serializers make of it is valid *output* under `v0.json`

Either alone is weak. Together they pin both ends of the contract, which is the
drift the audit was actually worried about. It uses the same Ajv construction as
`clients/validate.ts`, so the two cannot disagree about what valid means.

Session 48's experiment, reproduced: dropping `"aboard:relation"` from `edgeLD`
leaves `npx tsc --noEmit` at exit 0, because the serializers declare no return
types and the field simply vanishes from the inferred type. The new test fails
naming the field and the path.

`ajv` and `ajv-formats` are now root devDependencies. The audit gave their
absence as a reason the check had to stay CI-only; two dev-only packages already
present in `clients/` seemed a smaller cost than a documented hole that had
already cost four sessions a manual workaround.

### 2. A3, where the audit's prescription was wrong

The audit said tighten the timestamp fields to `z.iso.datetime()`. That requires
a time component, and every one of the twelve `resolutionDate` values in `data/`
is a bare calendar date. Following it literally would have rejected the entire
forecast corpus.

What landed instead is an `Iso8601` Zod schema copying the pattern from
`$defs/Iso8601` in `v0.json` character for character, applied to all six
timestamp fields. The audit said five; `Forecast.resolvedAt` is the sixth. The
point of A3 is that `types.ts` and `v0.json` should state the same rule, and
accepting less than we publish would have been a different bug from the one
being fixed.

The A3 gap was demonstrated before it was fixed, not assumed: a fixture with
`createdAt: "last Tuesday"` passed the Zod assertion and failed the schema one.

### 3. The loader was blaming the wrong file

A3's stated benefit was that bad data "fails the loader with a named file, not
the CI tail". Half of that was untrue. Planting the fault in real data produced:

```
Error: Failed to collect page data for /about/index.md
```

`about/index.md` has nothing to do with it; it is merely the page that happened
to touch the loader first. The field was named, the file was not.

`loader.ts` already had a `rel()` helper whose comment reads "so thrown errors
name the file a contributor has to open" — wired only to the not-a-list error,
never to the schema failures, which are the ones that actually happen. Now:

```
Error: data/inequality/claims/IL1.md: createdAt: must be an ISO-8601 date (YYYY-MM-DD) or date-time
Error: data/inequality/edges.yaml[0]: strength: Too big: expected number to be <=1
```

The index suffix matters for `edges.yaml`, which holds many entities per file.

### 4. strictObject, and the write-path change it made silently

All twelve data schemas flipped. The audit's "verified free today" was
re-verified rather than trusted, since `data/` has grown since July: the corpus
builds clean under strict.

The fault test that justifies the change is the optional field, not the required
one. A required-field typo already produced an error, just an unhelpful one. An
optional-field typo produced nothing at all:

```
Error: data/inequality/claims/IL1.md: sources.0: Unrecognized key: "authorss"
```

Before this, `authorss:` was silently dropped and the source quietly lost its
authors, with nothing reporting it anywhere.

Then the part worth recording. Flipping `Source` changed live write-path
behaviour, and all 428 tests passed without noticing. Probing directly showed
the two doors had come to disagree about the same payload:

| Door | Source carrying an unrecognised key |
| --- | --- |
| `POST /api/proposals` | 422, `Unrecognized key: "publisher"` |
| MCP `propose_claim` | stripped silently, proposal succeeds, metadata gone |

`worker/index.ts` states the invariant in its own header: an MCP write and an
HTTP write are the same write, with the same auth, the same rate limit, and the
same validation. So the mcp-server mirror is strict too, and both doors refuse.

One asymmetry was kept and documented: top-level payloads still *strip*
caller-supplied `id`/`authoredBy`/`createdAt` rather than refusing. An agent
that helpfully includes `createdAt` is not making a 422-worthy mistake, and the
posture is that the server stamps those regardless. Inside a source, an unknown
key is a typo worth refusing. Both halves now have tests.

### 5. The forecast port

`scripts/forecast-sanity.ts` was 30 assertions over the module the predictions
feature rests on, run by nothing. Session 7 wrote it as a pure-assertion script
because "no test framework exists in this repo"; one has existed since, so the
shape outlived its reason.

Ported to `src/lib/forecast.test.ts` as 29 tests covering all 30 assertions, and
the original deleted. A port that leaves the original is a copy, and two copies
of the same assertions is the duplication-drift this session spent its time
finding, with only one of them ever running.

The domain comments were kept, because they carry the argument rather than
decorating it: F4's median sits at 0.40 while its mean is 0.444, and dropping
the 0.65 outlier moves the median by exactly zero. Fault-tested by making
`median` return the mean, which turns seven tests red including the three
carrying that story.

## Decisions worth remembering

- **Fault tests found what reading did not.** Three of this session's changes
  were not in the plan: the loader naming the wrong file, the two write doors
  diverging, and A3's prescription being wrong. None was visible from reading
  the code or the audit. Each appeared within a minute of planting a failure.
- **An audit's prescription is a hypothesis, not an instruction.** The A3 entry
  was written by someone who had read `types.ts` and not the twelve forecast
  files. Checking the data first cost one grep and saved rejecting the corpus.
- **A change that no test notices is the one to look at hardest.** All 428 tests
  passed while `Source` going strict quietly tightened a live API. Green meant
  the behaviour was uncovered, not that it was unchanged.
- **Bound a shared schema at the door it is attacked through.** Bounds and
  strictness belong where the untrusted input arrives; pushing them into the
  shared schema changes contracts nobody was thinking about.
- **A port that leaves the original is a copy.** Deleting
  `scripts/forecast-sanity.ts` is what makes this a port. Two copies drift, and
  the one outside the gate drifts unobserved.
- **Consistency between two doors is a claim that needs a test.** The Worker
  header asserted both doors validate identically; nothing checked it, and they
  had diverged. The mirror is now checked as text, the way `enum-sync.test.ts`
  checks the enums, because no compiler in this gate reads that package.
