## What happened

### 1. The Dockerfile stopped being theoretical

The `Dockerfile` was written but unbuilt, because docker is not installed
on the authoring machine and the plan said so. Built and verified with
podman 5.8.2, the Dockerfile being plain OCI so podman builds it
unchanged: the image starts, reports `serverInfo` `aboard-mcp-server` at
0.1.1, answers `tools/list` with all nine tools, and runs as `node`
rather than root, at 187 MB.

That clears Glama's stated bar, which is only that the server starts and
responds to introspection. The plan now records the measurement instead
of the intention.

Worth keeping straight: it was the *host* stdio probe a day earlier, not
this one, that surfaced the `serverInfo.version` drift where the server
announced 0.1.0 from the published 0.1.1 with nothing able to see it. The
old text let those two run together.

### 2. The runbook

A numbered runbook for the server-listing route, steps 0 through 5, about
twenty minutes of operator time and all of it in a browser except step 0.
The parts that are judgement rather than clicking:

- **The order is not optional.** The badge URL 404s until the listing
  exists, so a badge added first is a broken image in the PR, which is
  worse than the omission session 71 chose deliberately.
- **Two check results that are expected, not defects.** The four
  `propose_*` tools decline without a credential, which is correct
  behaviour. And `prompts/list` answers `-32601` on the stdio server, a
  deliberate divergence from the remote endpoint argued in
  `src/lib/mcp/protocol.test.ts`. If that one does fail the check, that
  is new evidence and the decision is worth reopening rather than
  working around.
- **Read the score before advertising it.** A low score is a reason to
  fix something or skip the badge, not a thing to paste. It is the same
  judgement session 71 applied to the connector badge.
- **The fresh-clone identity trap.** Session 71 hit it: a clone with no
  git identity failed the commit while the push succeeded, briefly
  leaving an empty branch on the fork.

It also states what done means, which is that the listing passes, the
badge renders and the PR is updated. Not "the PR is merged": at 1,880
arrivals a month against 74 merges that is not a condition this project
can satisfy, and section 3 already records why the completion condition
was repriced to "filed".

### 3. Two corrections downstream

Section 3 still said the badge was omitted "because the connector
currently renders unhealthy". That was the wrong object, and the line now
says so: the badge in question is the server one, no server listing
existed yet, and the maintainer's mail asks for both. Section 4's snippet
was introduced with "if Glama has indexed by the time you open the PR",
which had been overtaken: the PR was filed on 2026-08-26.

## Decisions worth remembering

- **Two Glama badges exist, and they are different objects.** The
  connector badge reflects the remote Worker endpoint's health check; the
  server badge reflects the stdio package's listing. Session 71 reasoned
  about the first while the ask was about the second, and the conclusion
  it reached ("no badge") was right for the wrong reason and then wrong
  once the mail arrived. The stdio route sidesteps the connector check
  entirely, which is what makes it available while the other stays
  stuck.
- **When the ask is operator time, the deliverable is a runbook, not a
  narrative.** Section 1 was an accurate account of what had happened and
  useless for doing the next thing. The rewrite is what makes twenty
  minutes in a browser executable by someone who was not there.
- **An unmerged branch is not work in progress, it is work at risk.**
  This commit was complete on 2026-08-29 and delivered nothing for nine
  days, because a branch with no log cannot merge under the one-PR-per-
  session rule and nothing was watching for it. On the morning of
  2026-09-07 the maintainer commented on #12962 asking for exactly what
  this runbook describes, so it went from ready to overdue while sitting
  finished on disk.
