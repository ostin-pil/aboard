### 1. localStorage self-heal on schema drift (`70d3f20`)

`ClaimGraphRFInner`'s `initial` `useMemo` (`src/components/graph/
ClaimGraphRF.tsx`) now sanity-checks a rehydrated graph before trusting
it: in `fullbleed` mode it must contain at least one `domainGroup`

failure mode that ate the first hour of session 9 — stale
`aboard.graph.v3` with no group nodes) rehydrates into an inert graph;
the check detects that, calls `clearPersisted()`, and rebuilds from

"option 1" recommendation.

## Decisions worth remembering

1. **Pin the package manager rather than fight the churn.** The
   corepack `packageManager` field kept reappearing because there was no
   valid value; the injected `yarn` was also wrong for an npm project.
   Committing `npm@10.9.2` makes corepack stop rewriting it. Bump the
   value when npm is upgraded.
2. **The Lightning CSS `z-index` warning is unsuppressable and benign.**
   No directive, no config knob on Next 16.2.6 + Tailwind v4;
   declarations aren't dropped. Documented and accepted — do not churn
   the CSS chasing it.
3. **Self-heal validates structure, not a version number.** Rather than
   a brittle `STORE_SCHEMA_VERSION` bump (relies on devs remembering),
   the check asserts a structural invariant (fullbleed ⇒ ≥1 domainGroup)
   that any future refactor would also have to satisfy. Cheaper and
   harder to forget.
4. **Plans, not code, for the two deferred features.** The user asked
   for briefs so the context survives re-sessioning; both are written so
   a future session can execute without this chat, with the design forks
   surfaced explicitly.
