## Context

Session 71 measured that thirteen of fourteen requests to `/mcp` in a
four-minute window were `GET` or `HEAD`, every one answered 405, and
recorded a three-way fork: serve SSE, improve the 405 body, or leave it.
The hypothesis attached to it was that Glama's health checker probes
with `GET`, which would explain a badge that two sessions had failed to
clear.

## What happened

### 1. A fourth option, recommended and then withdrawn

Reading the code produced an option the issue did not name: answer `GET`
with a useful 200 JSON document, negotiated on `Accept` so a caller
asking for `text/event-stream` still received the spec-correct 405. It
had a precedent in the tree (`serveMarkdownTwin` is Accept-negotiated
with `Vary: Accept`) and it was the recommendation this session opened
with.

Research killed it. Returning 200 with a non-SSE body on `GET` is an
unhandled path in the official TypeScript SDK, in both published
majors: `_startOrAuthSse` checks `response.ok`, special-cases 405 with a
bare `return`, then pipes the body into the SSE parser with no
content-type check. The parser yields nothing, the stream ends, and the
reconnect scheduler re-seeds its counter, so `maxRetries` never trips.
Measured against a real client: 405 or 204 give one `GET` and no error;
400, 404, 406 and 501 give one `GET` and a harmless error; 200 with any
content type gives an unbounded loop at about one request per second,
forever, with `onerror` never firing. Tool calls keep working, which is
what makes it dangerous.

Two other server projects have shipped fixes citing exactly this.
`mcp-proxy` 6.5.1 added a stateless branch commented "return
METHOD_NOT_ALLOWED so stateless clients' transport stops reconnecting";
Python FastMCP 3.0 replaced a stateless `GET` that opened a
never-emitting socket with a 405 plus a test.

The Accept-negotiated variant would have survived on the letter of it,
since both SDK clients send an Accept containing `text/event-stream` and
would have taken the 405 branch. But the entire margin protecting
callers from a silent one-per-second loop would have been a substring
match on a header we do not control.

### 2. The premise was probably wrong too

The strongest evidence on Glama's prober is a maintainer reading their
own gateway's log: every Glama health test is one `POST /mcp`. Three
more describe an unauthenticated `initialize` plus `tools/list`. One
report claims `GET` and reads as inferred from a 404. Glama documents
nothing about probe mechanics anywhere. So the fix was aimed at the half
of the hypothesis that is least likely to be true.

`Disallow: /mcp` in `robots.txt`, planned alongside, was dropped for a
separate reason found before shipping it: a disallow blocks the fetch
but not the indexing, and Google indexes a disallowed URL from external
links as "Indexed, though blocked by robots.txt". `/mcp` is externally
linked from the README, the server card and the awesome-mcp-servers PR,
so it would have created the Search Console warning it was meant to
prevent. With the 405 kept, neither a disallow nor a `noindex` is
needed.

### 3. What shipped instead, none of it aimed at the badge

**Telemetry.** `mcp_probe` records requests to `/mcp` that reach no
tool, with the method, a folded agent class and an accept class. Session
71 could only see this traffic through a live `wrangler tail`, which
sees the window someone is watching; Analytics Engine timestamps each
row, so a checker publishing when it last tested can be correlated
against what arrived.

The second commit is the one the research earned. `mcp_call` fires only
on `tools/call`, so a caller that speaks the protocol correctly and
stops after `initialize` left no trace at all — which is exactly the
shape the evidence says Glama's probe has. The point now covers
handshake POSTs too. `OPTIONS` stays uncounted (a preflight is a CORS
mechanism, not a caller) and a `tools/call` is still counted once, which
is pinned by a test.

**Two conformance fixes.** `POST /mcp/` returned 404 because the route
matched exactly, which is indistinguishable from an absent endpoint to a
prober that normalises the trailing slash. The audience is unaffected:
`normalizeResource` already treats the two spellings as one resource,
the way RFC 8707 requires, so the precedent for tolerance was already in
the file.

`prompts/list` now answers with an empty list instead of `-32601`. This
revises half of a decision `src/lib/mcp/protocol.test.ts` had pinned,
with an argument, from when Smithery was the only scanner calling an
undeclared method. Glama's published methodology runs `prompts/list`
unconditionally as part of introspection, which makes it the behaviour
of introspection tooling rather than one vendor's quirk. The half that
test exists to defend is untouched: the capability is still undeclared,
and declaring one this server does not have is still refused.

### 4. The mail, and the distinction three sessions had missed

A message from the awesome-mcp-servers maintainer arrived mid-session,
framed as updated listing requirements: list the server on Glama, pass
its checks, add the score badge to the PR.

Glama has **connectors** and **servers**, and every session up to this
one worked only the first. A connector is a hosted HTTP endpoint, ours
being `/mcp`, health-tested on Glama's own schedule. A server is a
repository listing, verified by building a Dockerfile and checking the
process starts and answers introspection. Different URLs, different
checks, different badges.

The badge the mail asks for is the **server** badge, so the connector's
unhealthy state does not block it, and session 71's reason for omitting
it ("an unhealthy badge is worse than none") was correct about the
connector and does not apply. The server route also sidesteps the
problem entirely: it runs `mcp-server/`, which never touches the Worker.

### 5. Running the stdio server found two defects

The `Dockerfile` is two-stage, non-root, runtime dependencies only, with
a `.dockerignore` so the Next.js app never enters the build context. It
is **unbuilt**: docker is not installed on this machine. What was
verified is the substance it packages, the built stdio server answering
`initialize`, `tools/list` and `prompts/list` over real stdio.

That probe found `serverInfo.version` announcing `0.1.0` from the
published `0.1.1`. Every client of the npm package has read the wrong
version since the bump, and nothing could see it: the literal is
hand-written because `rootDir` is `src/`. Fixed and pinned to
`package.json` by a parity test, the same shape as session 69's
`mcpName` pin, verified by planting a mismatch.

The pin then broke `check:exports`, by the mechanism `knip.jsonc`
already documents. The test named `src/index.ts` in a `new URL(...)`
literal; knip follows those into the file and reached the MCP SDK
import, a dependency of `mcp-server` but not of the root package knip
reads. Deriving the path at run time keeps the test and leaves the gate
honest.

### 6. The connector lever

`/.well-known/glama.json` is published, claiming ownership against a
matching maintainer email. It is the only lever that exists on the
connector side: there is no re-scan button and no documented re-check
request. Whether it is worth pulling is another matter — roughly 40% of
15,045 Glama connectors show unhealthy, Linear, Notion, Atlassian and
Sentry among them, and no case was found of anyone getting one
un-stuck.

## Decisions worth remembering

- **A safe fix aimed at a false premise is still the wrong fix.** The
  Accept-negotiated 200 would not have broken any known client. It was
  dropped because its payoff rested on a hypothesis the evidence
  contradicts, and its safety rested on a header nobody controls.
- **The 405 is load-bearing, not merely permitted.** Two server projects
  shipped fixes to return it specifically so clients stop reconnecting.
  Reachability and correctness came apart here, and correctness won on
  evidence rather than on principle.
- **Instrument the thing you cannot see before arguing about it.** Two
  sessions debated a caller nobody had measured. `mcp_probe` exists so
  the third does not have to.
- **A pinned decision can be half right.** The `prompts` test defended
  two claims at once, and only one of them survived new evidence.
  Separating them kept the argument that still holds.
- **Verifying the substance beats verifying the wrapper.** The Docker
  image could not be built, but running what it packages found a version
  drift that had survived every gate in the repo.
- **Three sessions read one badge as one object.** Connector and server
  are different things on Glama, and the whole investigation was aimed
  at the one the mail was not about.
