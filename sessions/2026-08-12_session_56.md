## What happened

### 1. knip's defaults describe a different repo

Run bare, knip reported 19 unused files, 3 unused dependencies and 25 unused
exports. Almost all of it was one mistake compounding: it did not know where
this repo is entered from, so it called `worker/*.ts` unused, then called the
dependencies only those files import unused, then called the `src/lib/mcp/*`
exports only those files consume unused.

The entry points it cannot infer are now written down in `knip.jsonc`. The
one worth naming is the Worker: `wrangler.jsonc` names only `worker/index.ts`
as `main`, and `mcp.ts` and `oauth.ts` are reached through the OAuth
provider's config object rather than a static import, so no resolver can
follow the edge. All three are listed by hand. With that in place the file
and dependency reports went empty and stayed empty.

`clients/` and `mcp-server/` are out of scope rather than ignored for
convenience: both are independent packages with their own tsconfig and their
own gate command, and neither has an import reaching into `src/`, which was
checked rather than assumed. That is what makes excluding them safe.

### 2. Thirty findings, three different answers

The remaining 30 findings did not want one fix. Sorted by whether the symbol
has a real reference inside its own file, excluding comments and the
declaration line:

| Verdict | Count | What it means |
| --- | --- | --- |
| Un-export | 24 | Used, but only by its own module. Keyword goes, code stays |
| Delete | 3 | No reference anywhere in `src/`, `worker/`, `scripts/` or tests |
| Exempt | 3 | The tool is right about the facts and wrong about the conclusion |

The three deletions were `getEdges` and `getAnalysis`, accessors in the graph
layer with no call site, and `_resetGraphCache`, whose comment offers it to
"the migration script + tests" when there is no migration script and no test
resets the cache.

The exemptions are `SourceKind`, `AnalysisKind` and `ResolvedOutcome` in
`src/lib/types.ts`. That file pairs `export const X = z.enum(...)` with
`export type X = z.infer<typeof X>` for every schema, and for these three
nothing currently imports the runtime half. Un-exporting exactly three of
about twenty schema constants would break the file's own rule to satisfy the
tool, so the file is named as an entry point with the argument written next to
it. A contract file is where "no importer" stops meaning "delete it".

A caution that came out of checking rather than trusting: a plain grep said
`SERVER_INFO` was referenced from `worker/oauth.ts` and `resources.ts`, and
`SERVER_INSTRUCTIONS` from `tools.ts`. Every one of those was prose in a
comment. knip was right and the grep was the noisy instrument.

### 3. The measurement

Same method as sessions 45, 46, 48 and 53. Plant the fault, run the gate,
record what fires. An exported function in `src/lib/site.ts` that nothing
imports:

| Command | Result |
| --- | --- |
| `npx tsc --noEmit` | exit 0 |
| `npm run lint` | exit 0 |
| `npm test` | exit 0 |
| `npm run build` | exit 0 |
| `npm run check:exports` | exit 1, naming `src/lib/site.ts:30` |

The blindness is structural, not an oversight. `tsconfig.json` does not set
`noUnusedLocals`, and an exported symbol is used as far as eslint's
`no-unused-vars` is concerned. A declaration nothing imports passes every
other command in the gate indefinitely, which is why session 54 could only
find `useGraphInstance` by reading the code.

### 4. Wiring

`check:exports` went into `build_commands` beside a `Check exports` step in
`ci.yml`, with `check:config` holding the two in parity. The manifest note
argues the glob, which needed an argument it did not need for the earlier
sessions: `*.ts` and `*.tsx` already had readers. The point is that they had
readers which could not see this class of fault.

## Decisions worth remembering

- **A stale read looks exactly like an empty branch.** The first checks of
  session 55 returned a clean tree at `origin/main` while an agent was
  committing to it. Nothing in that output said "stale". What settled it was
  sampling twice and comparing mtimes and line counts, plus `ListAgents`. Any
  claim that a branch is idle should be built on two observations separated in
  time, not one.
- **Pick the slice by who owns the files, not by what is interesting.** Session
  55 held the whole graph directory. The four `src/components/graph/types.ts`
  edits here were made only after checking that session 55 had not touched that
  file and referenced none of the four symbols.
- **A gate's value is what it can see that the others cannot.** `*.ts` already
  had four readers. The argument for a fifth is the measured fact that none of
  them fails on a dead export.
- **The tool being right does not make the fix right.** The three `types.ts`
  schemas are genuinely unimported and genuinely should stay exported. An
  exemption with the reasoning next to it is a better artifact than a
  consistent-looking file that broke its own convention.
- **Grep is the wrong instrument for "is this used".** Three of the findings
  had apparent outside references that were all comment prose.
