### 3. Chunk 4 verification: the pipeline, and a red herring

The first SQL query returned rows, but not the probe events this
session had just fired, which looked like a wiring gap in exactly the
Worker seam vitest cannot reach. It was not. `SELECT NOW()` anchored
the server clock and showed the query's `NOW() - INTERVAL '1' DAY`
window began after the probes had fired, the probes and the query being
nearly a day apart in wall time. The WHERE clause had excluded them.

Fresh probes settled it properly: all three event kinds (`twin`,
`mcp_call`, `proposal`/unauthorized) written and read back through the
SQL API within 45 seconds of firing. Chunk 4's exit criterion is met
with the exact query `worker/README.md` documents.

## Decisions worth remembering

- **Deploy verification is a session's work even when the deploy is a
  command.** Both residue items existed because merged code had never
  met production. The gap between "gate green" and "verified live"
  held a provisioning failure and a wrong claim in two files.
- **Anchor the clock before diagnosing missing telemetry.** The
  missing-events scare dissolved on `SELECT NOW()`: the query window,
  not the pipeline, had excluded the probes. Cheaper than the Worker
  wiring audit it nearly triggered, and the right first move whenever
  a time-filtered query disagrees with what you did.
- **A falsified claim gets corrected where it lives, immediately.** The
  "nothing to provision" line was one deploy old when it broke; PR #97
  landed the measured version the same day, not a tracker entry
  promising to.
- **Permission routing across sessions worked as designed.** Session 61
  could not rebase, did not ask this session to, and this session did
  not offer; the operator ran the one line. The laundering guard cost
  nothing and kept both audit trails honest.
