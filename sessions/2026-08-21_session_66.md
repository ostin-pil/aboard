## What happened

### 1. `src/lib/tokens.ts`, and the count the plan got wrong

The audit said 59 re-typed hex values. Measured, the three OG cards hold
45 across 15 distinct colours; 59 was the whole tree, which includes
`consent.ts` and `persist.ts`. The 45 are the ones that matter, because
Satori resolves no cascade and no `var()`, so the cards genuinely cannot
read `globals.css` and every colour has to arrive as a literal.

That is the whole justification for the module, and it buys a problem:
the palette now exists in two languages with nothing relating them.
`tokens.test.ts` is the relation. It parses the custom-property blocks
out of `globals.css` and asserts each token still equals the property it
mirrors, that light `--grid-dot` really does hold `--line-2`'s value as
the token assumes, and that no hex literal has returned to the three
card files. Both fault classes were planted and caught.

One colour is recorded rather than corrected. The `·` separating facts
on the claim card is `#a8a29e`, which mirrors no light property: it is
the *dark* theme's `--muted`, and it reads as a hairline against the
light background, so nobody caught it. Changing it would re-render every
claim card, which is a design decision and not a refactor. The test pins
it to the dark `--muted` so it cannot drift into being wrong twice.

The refactor claim was checked rather than asserted: `main` and this
branch were both built and all 31 rasterized cards came out
byte-for-byte identical.

### 2. E19 — the dark palette, defined once

Dark is selected two ways, and both are structural. `[data-theme="dark"]`
is the explicit choice; the media query covers the default "system" mode,
which sets no attribute, because `themeBootstrap` in `layout.tsx` writes
the attribute only for an explicit light or dark, which is what leaves a
visitor with JS off their system preference. CSS cannot put a selector
and a media condition in one rule, so neither block can go.

What could go was each block carrying its own copy of the values: 33
tokens written twice, in two different formats (one per line in the
first, packed several per line in the second), which is exactly what
made reading them against each other hopeless. The values move to one
`--dark-*` source block and both selectors now alias it, holding no
value of their own.

`tokens.test.ts` gained the checks: the two alias lists must be
identical (so a dropped line fails as well as a changed one), neither
block may restate a literal, every alias must resolve to a source token,
every source token must be aliased, and dark may not override a token
light never defines. Three drift faults planted and caught. Before the
rewrite the two blocks were verified to agree; after it, both were
verified to resolve to `main`'s 33 values exactly, with the light block
untouched.

Considered and rejected: `light-dark()`, which is the tidier answer for
colours but takes only colours, leaving `--dossier-bw`, `--grid-dot-alpha`
and the two shadows (whose geometry differs, not just their colour)
duplicated anyway, and which changes what ships to browsers in a way
this repo's browser pass is poorly placed to verify.

### 3. `ECE3` — the first `evidences` edge

`ECM2 evidences ECL1`: measurement error of the size Freedman et al.
found is the reason to believe better-identified designs beat more
cohorts. The relation is support rather than production, since the
mechanism does not make the designs work; it is what makes the
alternative fail. The rationale scopes itself to that limb, because ECL1
also recommends randomized trials on hard endpoints that this evidence
does not reach.
The Freedman validation pooling is attached to the edge as its source.

The plan asked for a dataPoint-backed claim supporting a *mechanism* and
that shape does not exist in this graph. Enumerated: ten claims carry
non-empty `dataPoints`, and every dataPoint-backed symptom among them
already has a causal edge to the mechanism it would evidence, so any
symptom-evidences-mechanism edge would have been the mirror of an
existing one. The relation with no available causal reading ran
mechanism-to-leverage instead.

Two checks before writing it. Session 65's `relationKey` includes
direction, and its comment calls a reverse edge a contradiction rather
than a duplicate, so the shape had to not be one; and React Flow edge
ids are `${from}->${to}#${kind}#${i}`, so a distinct kind cannot collide.
Neither concern applied in the end, because the edge runs between a pair
with no existing edge at all: `ECM2` had no relation in either direction
before this, which makes the seed's one agent-proposed mechanism
connected for the first time.

Verified in the built export rather than assumed: `aboard:relation:
"evidences"` with its `schema:citation` on `/api/graph` and in the
embedded JSON-LD on both claim pages. That turns session 49's fix from
test-proven into data-proven, which is what `research/schema.md` had
been carrying as known inconsistency 7; it moves to resolved, and the
schema's "'evidences' is reserved" description is retired.

### 4. a11y — 6 rules to 31, and what they found

`eslint-config-next` registers the jsx-a11y plugin but enables six of its
39 rules, all as warnings. The recommended set now runs at error level,
so a finding fails `npm run lint` instead of adding to the count the
`--max-warnings 0` ratchet is aimed at. Re-registering the plugin is a
hard config error, so only its rules are taken.

Nine findings across six files, settled three ways.

Two were real and are fixed. The JSON-LD export's `<pre>` was a tab stop
with no name (it must be focusable: a scrollable box keyboard users
cannot reach is WCAG 2.1.1), now a labelled `region`, with the rule's
allow-list widened to match and the reason written at the config. The
modal backdrop now carries `role="presentation"`, which is true of it and
leaves Escape as the keyboard path it already had.

Two are the rule over-reaching. Both `autoFocus` sites are on an input
that does not exist until the user asks for it, so focusing it answers
the request rather than stealing focus on arrival.

Four are one real gap: nodes and edge labels on the canvas are
pointer-only. The obvious repair makes it worse. React Flow already
makes its own node wrapper focusable, so a tab stop on the inner div
gives every node two across a canvas of about thirty, and keydown does
not reach a child from a focused parent, so the handler cannot sit where
the click handler sits. Filed in `knowledge/issues.md` with the two
disables pointing at it.

`a11y.test.tsx` adds what a linter cannot see. eslint reads the source;
axe reads the rendered tree, and the faults in that gap are the ones only
rendering exposes. Both were planted and caught: an unlabelled control,
and an `aria-labelledby` whose id never reaches the DOM. The three
dialogs are rendered rather than mocked up in HTML, which `focus-trap.test.ts`
can do because what it tests is a selector; a fixture cannot verify the
markup a component actually emits.

`eslint-plugin-jsx-a11y` and `axe-core` were both transitive through
`eslint-config-next` and are now declared. A gate an unrelated dependency
bump can silently remove is not a gate. The lockfile gained two lines and
no resolution changed.

### 5. E20 decided: keep

Measured by building both ways rather than by reading the import.
Tailwind contributes 13,699 bytes and not one utility class, so the
finding's premise is exactly right. Its conclusion is not: all of that is
preflight, and the built pages carry unclassed prose out of the Markdown
renderer: 144 `<a>`, 116 `<li>`, 35 `<p>`, 6 `<h2>`, 4 `<ol>`, 3 `<ul>`,
a `<table>` and 12 `<summary>` across 36 pages. Dropping the dependency
turns unclassed links browser-blue, returns bullets and heading sizes,
and un-collapses the table.

The components themselves do not lean on it (`.btn-mono` sets
`appearance: none` with its own background and border, and `list-style`
is set in nine places), so replacing preflight with an owned reset is a
real option later. It is a visual change wanting a browser pass, not a
dependency deletion, and it is recorded that way.

## Decisions worth remembering

- **A refactor that changes rendered output is checkable, so check it.**
  Building `main` and the branch and comparing all 31 OG PNGs by hash is
  what makes "no behaviour change" a fact rather than a hope, and it cost
  one extra build.
- **Duplication you cannot delete, you can still make single-source.**
  CSS genuinely cannot express "this selector or that media condition",
  so the two dark blocks are permanent. Aliasing a single source block
  removes the drift without pretending the structure can go away.
- **The audit's premise can be right and its conclusion wrong.** E20's
  "zero utility classes are used" is exactly true; "therefore drop the
  dependency" does not follow, because the 13,699 bytes are the site's
  reset. Measuring both builds is what separated the two.
- **A plan's parenthetical describes a shape that may not exist.** Chunk
  9 asked for a dataPoint-backed claim supporting a mechanism; the seed's
  causal edges are complete enough that no such edge could avoid being a
  mirror. Enumerating the ten dataPoint-backed claims turned a vague
  unease into a stated reason for deviating.
- **eslint and axe are not redundant.** One reads source, the other reads
  the rendered tree. The planted `aria-labelledby` pointing at an id that
  never renders is invisible to the first and obvious to the second.
- **Declare what a gate depends on.** jsx-a11y and axe-core both worked
  transitively; neither would have survived a dependency bump, and
  nothing would have said so.
- **A merged parallel session can fail your lint for its own reasons.**
  `react/no-children-prop` fired only after the merge, on this session's
  own file. Re-running the full gate after resolving a conflict is not
  ceremony.
