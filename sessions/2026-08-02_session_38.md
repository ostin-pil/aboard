## What happened

### 1. The ensemble now drops model citations by default

Session 36's audit found 20 of 56 model-authored URLs in committed forecasts
dead or fabricated, and added `--no-model-sources` as an opt-out. A project
whose core rule is that every URL in `data/` be a real landing page should
not default to writing invented ones, so the flag inverted: dropping
`baseRates` and `dataAnchors` is now the default, and `--model-sources` is
the explicit opt-in, with help text that says to verify each URL by hand
before committing. `--no-model-sources` still parses as a no-op so older
invocations do not break.

### 2. Supersession became data, and the lint became a gate

The stated precondition for `--strict` was met (F4 and F5 superseded by the
short-horizon slate) but the corpus had no way to say so: the lint still
flagged both originals every run. The wrong fix was an allowlist buried in
the lint script, invisible to readers and against data-as-source-of-truth.

Instead `Forecast` gained `supersededBy`, an optional non-empty array of
forecast IDs. Per CLAUDE.md the field moved through `types.ts`,
`public/schema/v0.json`, `jsonld.ts` (as `@id` references) and
`research/schema.md` in one commit. Referential integrity rejects unknown
targets and self-reference, with tests. F4 now names F7; F5 names F6 and
F8, matching session 36's replacements. The YAML comments say why criteria
stay as filed: the predictions above them answered those questions.

`lintForecast` skips a superseded forecast, and the CLI prints what it
skipped rather than passing silently:

    Superseded, not linted (criteria are historical record):
      democratic_backsliding/F4 → F7
      democratic_backsliding/F5 → F6, F8

With the live corpus reporting clean, the decision on where strict lives:
`build_commands` in the lifecycle manifest, so session-end gates on it,
while `npm run build` stays un-gated. That keeps prose heuristics out of
the product build and still means a session cannot land a forecast a
distrustful reader could not settle.

## Decisions worth remembering

- **Supersession is data, not lint config.** An allowlist in the lint
  script would have hidden the signal from every reader and agent; a
  schema field makes the repair path machine-readable and referentially
  checked.
- **Strict gates session-end, not the product build.** Prose heuristics
  have no business failing `npm run build`; they have every business
  blocking a session from landing an unsettleable forecast.
- **Re-verify carried follow-ups against the repo before working them.**
  The AgentAttribution item survived six sessions because each log copied
  the previous one's claim instead of grepping the schema. The check took
  one command.
- **Commit-time branch verification is missing.** Six commits landed on
  another session's branch because `git commit` trusts HEAD and HEAD had
  moved under this session. Worktree-first at session start would have
  prevented it; so would a pre-commit assert that the current branch is
  the session's own.
