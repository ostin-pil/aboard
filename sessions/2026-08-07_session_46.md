## What happened

### 1. The `.js` glob was hollow and `.mjs` was missing

`"*.js"` had been in `code_globs` since the manifest was written. Today it
matches only `Claude Design Screens/assets/*.js`, the imported mockups, because
`public/graph-engine.js` was deleted when the graph moved to React Flow. And
`"*.mjs"` was absent, although `scripts/check-built-urls.mjs` is real code that
CI runs at `.github/workflows/ci.yml:70`.

Tested the way session 45 tested shell, by planting a syntax error in
`scripts/check-built-urls.mjs` and running the gate against it:

| Command | Result against an unparseable `.mjs` |
| --- | --- |
| `shellcheck $(git ls-files '*.sh')` | exit 0 |
| `npx tsc --noEmit` | exit 0 |

| `npm run check:built-urls` | **fails**, module link error |

The configs say why. `tsconfig.json`'s `include` is `**/*.ts`, `**/*.tsx` and
`**/*.mts`; `*.mjs` is not `*.mts`, and `allowJs` does not widen `include`.
Vitest reads `src/**/*.test.ts`. So the whole gate was blind to a file CI runs.

### 2. The fix is a pair, again

`eslint` is the only command in this gate that reads either extension, so
`"*.mjs"` went into `code_globs` and `npm run lint` went into `build_commands`.
Either alone is useless: the glob without the command classifies a session as
code and then verifies nothing, and the command without the glob never fires,
because a `.js`-only change still classifies as docs and skips phase 1.

`npm run lint` was already a hard gate in CI (`ci.yml:51`) and was simply
missing from the session gate. On a clean tree it exits 0 with 13 warnings, so
adding it does not fail sessions on the existing warning count. Confirmed both
directions: broken `.mjs` exits 1, restored tree exits 0.

The comment above `code_globs` now pairs every glob with the command that reads
it, so the next person to widen it inherits the test rather than the habit.

### 3. Documentation described a renderer deleted months ago

`CLAUDE.md` listed `public/graph-engine.js` as the live renderer in the
architecture section and again in the file-layout map, and described
`ClaimGraphCanvas.tsx` as a "React wrapper around graph-engine". `README.md`
carried the same line. The file does not exist.

What is actually there is `src/components/graph/`, seventeen files around
`ClaimGraphRF.tsx`. `ClaimGraphCanvas.tsx` mounts it and picks inline or
fullbleed.

Worth recording why the stale text read as plausible: `src/lib/engine-adapter.ts`
and `src/components/graph/engine-to-rf.ts` both still say "engine", because the
`EngineGraphData` shape outlived the vanilla-JS engine it was built for. The
name survived the thing. Both docs now say so.

`plans/code-quality-audit.md:223` had already flagged this. That entry can
close.

## Decisions worth remembering

- **A glob and a command that reads it are one change.** Third time this shape
  has appeared: shell in session 45, `.js`/`.mjs` here. Widening `code_globs`
  alone converts a session that verified nothing into one that runs a green
  gate and still verifies nothing, which is worse, because green reads as
  verified.
- **`allowJs` does not widen `include`.** `tsconfig.json` sets `allowJs: true`,
  which makes JavaScript loadable when something imports it, and changes
  nothing about which files `tsc` reads on its own. `**/*.mts` also does not
  cover `*.mjs`. Both look like coverage and are not.
- **CI and the session gate drift apart silently.** `npm run lint` had been a
  hard CI gate for sessions while being absent here. Nothing reports that
  divergence, so it is worth reading the two lists against each other whenever
  either changes.
- **A name can outlive the thing it named.** `engine-adapter.ts` and
  `engine-to-rf.ts` kept "engine" after the engine was deleted, which is
  exactly why the stale documentation stayed believable for months.
