### 3. Why A6 survived two audits

`worker/index.ts` exported exactly one symbol, the default handler. Nothing
could unit-test the PR-body builders, so no gate in the repo could see them.
That is the finding behind the finding, and the fix had to start there: the
four builders and their helpers moved to `src/lib/pr-body.ts`, which is pure
and covered by `pr-body.test.ts`. The Worker's own header already said that is
where decisions belong.

The injection inventory was larger than the audit recorded. Beyond `rationale`
and `statement`, `claim.domain` and both dossier theses were interpolated raw.

Containment, by shape of value:

| Value | Containment |
| --- | --- |
| rationale, statement, theses | code fence, length computed from the content |
| domain, identity fields | code span, newlines flattened |
| source labels | escaped, newlines flattened |
| source URLs | http(s) by schema (A5), angle-bracket destination |

The fence length is the part that matters. A fixed three-backtick fence is not
containment: a caller who writes three backticks inside the rationale closes it
and everything after is live markdown again. Counting the longest backtick run
in the content and opening with one more is what makes the block inescapable.
`pr-body.test.ts` runs an attacker payload carrying a forged provenance block
and a pre-ticked checklist through all four builders and asserts the rendered
body has exactly one top-level `## Provenance` and zero ticked boxes.

That work also fixed a live rendering bug nobody was looking for. Source links
used a bare `(url)` destination, which breaks on any URL with unbalanced
parentheses, so every Wikipedia article with a disambiguator rendered wrong.

### 5. Two design calls that went against the first draft

**A9 validates per entry, not per table.** The first version rejected the whole
token table when any entry was malformed, on the reasoning that a typo should
be loud. That converts one mis-typed credential into an outage for every other
credential in the table. Both orders are equally safe, since no unvalidated
entry can become an identity either way, so the one without the availability
cliff wins. The mis-typed credential still gets its own 401.

**E11 stays quiet when another check owns the mistake.** The first version
double-reported: a claim declaring a nonexistent domain produced both "not a
directory under data/" and "declares X but sits in Y", and a duplicated id
produced a location error against an arbitrary one of its files. Both are now
suppressed, so one error means one problem.

### 6. Bounds sized against the real constraint

The limits are not round numbers picked for looking reasonable. GitHub rejects
a PR body over 65,536 characters with a 422 that reaches the agent as an opaque
`github_failed`, so the test that fixes the sizes renders the largest legal
claim proposal and asserts it fits. It comes to 41,470 characters. If a limit
is ever raised, that test is what should stop it.

## Decisions worth remembering

- **A finding that survives repeated audits usually has a structural reason.**
  A6 was not missed twice by inattention. The code lived in a file that
  exported nothing, so no test could reach it and no gate could see it. Moving
  it was the fix; the escaping was the easy part afterwards.
- **Containment has to be computed from the content it contains.** A fixed
  fence, a fixed delimiter, a fixed escape list against a fixed alphabet are
  all closable by an attacker who has read the source. The fence length here is
  derived from the longest backtick run in the caller's own text.
- **Bound a shared schema at the door it is attacked through, not everywhere.**
  Bounds on the write path belong in `proposals.ts`; putting them on `Source`
  would have retroactively invalidated committed content that is fine.
- **Fail closed, but scope the blast radius.** Per-entry token validation and
  whole-table validation are equally safe. Only one of them turns a typo into
  an outage.
- **Size a limit against the constraint that will actually bite.** The PR-body
  ceiling is GitHub's 65,536 characters, so the test renders the worst legal
  proposal rather than asserting the numbers look sensible.
- **One mistake, one error.** New integrity checks that overlap existing ones
  should defer to them, or a single typo reports three times and the reader
  starts skimming.
