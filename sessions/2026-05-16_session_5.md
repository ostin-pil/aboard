### Round 2 — the four reported defects (this conversation)

User retested and filed four issues. Each traced to a concrete root
cause and fixed smallest-first:

1. **Edited node disappears (`2b78852`).** `ClaimNode` passed a synthetic
   `position:{0,0}` into `openNodeEditor`/`openNodePopover` because
   React Flow's `NodeProps` doesn't expose `position`. That bogus
   position rode through `NodeEditorModal`'s `{...node}` spread and
   `onNodeSave` overwrote the live node at (0,0) — off-screen in
   fullbleed, so it looked deleted. Fixed by changing the context
   contract to take an `id`; the parent looks up the live node from
   state. `onNodeSave` also preserves `position`/`parentId` as a
   belt-and-braces guard.
2. **Edit/save controls too small (`72fb2f4`).** 28×28 always-visible
   pencil with a real SVG (not the ambiguous `✎` glyph); bolder modal
   primary button.
3. **New edge doesn't render (`a0659d3`).** `onConnect`/`onEdgeSave`
   dropped `sourceHandle`/`targetHandle`; with 6 handles per node, RF
   fell back to DOM-order defaults and (with `onlyRenderVisibleElements`)
   the edge routed wrong or got culled. Carry handle ids through
   `editingEdge`, the new edge, and the persisted shape.
4. **Drag-to-connect only worked off the handle dots (`a9a300b`).**
   Added a full-card target Handle that only mounts during a connection
   drag (`useConnection`), with a dashed hover affordance.

Plus the persist/group fix the four shared a root with:

- **`78428fe`** — `5a40e2d` removed `zIndex:-1` from `engine-to-rf.ts`
  but missed the hydrate path in `persist.ts`, so every refresh
  re-buried the group header. Bumped `STORE_KEY` to `aboard.graph.v3`
  (legacy v2 auto-cleaned on load) and removed the stale `zIndex`.

## Decisions worth remembering

1. **Y-axis stays semantically locked; only X is free-form.** Rows carry
   meaning (symptom=1 / mechanism=2 / leverage=3) and `rfToEngine`
   serializes `data.row` verbatim into the JSON-LD. Free-form vertical
   alignment would silently desync the published claim structure from
   the visual layout. So align/distribute is horizontal-only; vertical
   is "align row," which snaps onto a real row and updates `data.row`
   *and* `position.y` together. This is the right default for aboard's
   methodology-first thesis — revisit only if the user explicitly wants
   visual ≠ exported structure.
2. **`NodeProps` has no `position` — never synthesize one.** The
   "disappearing node" bug came from faking `position:{0,0}` to satisfy
   a type. The fix pattern: pass an id, resolve the live node from
   `nodesRef.current` in the parent. Any future "open editor/popover
   from a custom node" must follow this, not reconstruct a node object.
3. **Transient handles must normalize to null.** The full-node drop
   `Handle` only mounts during a drag (`useConnection`). An edge may
   never reference a handle that isn't present at rest, or it dangles
   and won't render/persist. `onConnect` strips `full-*` handle ids.
4. **Partial fixes that span two code paths.** `zIndex:-1` lived in both
   `engine-to-rf.ts` and `persist.ts`; fixing only the first masked the
   bug behind a fresh-load vs hydrate-load distinction. When a value is
   set in both the build and hydrate paths, fix both in the same pass.
5. **Coordinate space is per-node, not per-selection.** Grouped children
   use parent-relative coords; ungrouped claims use absolute. Both the
   grouping path (`f7980ef`) and align-row (`0126fc2`) bit on computing
   one offset and applying it to all. Always derive offset from each
   node's own `parentId`.
6. **`localStorage` versioned, not migrated (continued).** v2 → v3 on
   the group-structure change; legacy keys removed on load. Consistent
   with session 4 decision 3 — app isn't deployed, no migration logic.
7. **Shared `--ctl-*` tokens, not a visual redesign.** "Redesign the
   controls" was scoped to a consistency pass (uniform height/padding/
   radius/font across `.btn-mono` / `.ag-tool-btn` / bulk toolbar), not
   a from-scratch reinvention — that would be unbounded and is better
   driven from a Claude Design mockup if the user wants it.
