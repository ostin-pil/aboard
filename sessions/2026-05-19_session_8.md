## What happened

### 1. Diagnosed the "ahead 1" puzzle

`git status` reports ahead/behind against a branch's *configured
upstream*, not against whatever ref you reset to. `git reset --hard
origin/main` moved the local `docs/session-7` pointer to `cb66ee1` but
left its tracking config pointing at the (now stale) `origin/docs/session-7`
at `48d9fc3`. The "ahead 1" was simply the PR #6 merge commit — nothing
to reconcile. Confirmed with `git rev-list --left-right --count` → `0 1`.

### 2. Local branch cleanup (empirical evidence for the skill)

Seven merged local branches deleted; `origin` untouched (user chose
local-only). Five went via safe `git branch -d`. Two — `docs/session-7`,
`track-b-editor` — were *refused* by `-d` ("not fully merged") even
though git itself reported them merged to HEAD: their upstream was the
stale/merged PR head. Force-deleted with `-D` **only after** cross-checking
both were in `git branch --merged main`. This run became the design
evidence for the skill below.

### 3. Codified `/prune-branches` + `session-start` hook

Decision (via AskUserQuestion): a dedicated micro-skill plus a one-line
read-only hook in `session-start`, rather than AGENTS.md (sharply scoped
to the Next.js warning) or inlining into `session-start` (whose mutation
scope is deliberately conservative). New `.claude/skills/prune-branches/SKILL.md`:
hard preconditions (on `main`, `main == origin/main`, clean tree —
abort, not warn); gate on `git branch --merged main`; batch `-d` →
cross-check refusals against the merged set → single confirmed `-D` of
the verified subset; print recovery SHAs; never touch `origin`.
`session-start` step 1 now counts stale merged branches; step 6 surfaces
"run `/prune-branches`" with a note to do it before the step-7 branch
switch. Advisor review sharpened it: preconditions abort rather than
warn, the load-bearing invariant is stated explicitly at the top of
`## Rules`, and the `-D` confirm prompt explains *why* it is safe so the
gotcha is taught every time.

## Decisions worth remembering

1. **`git status` ahead/behind is vs the branch's configured upstream,
   not the ref you reset to.** `git reset --hard origin/main` repoints
   the local branch but leaves tracking config intact; a residual
   "ahead N" after a merged PR is just the merge commit.
2. **`git branch --merged main` on an up-to-date clean `main` is the
   load-bearing safety invariant for branch deletion.** `git branch -d`
   false-negatives on branches whose upstream is the merged/stale PR
   head; `-D` is safe *iff* the branch is in that list. Never `-D`
   outside it. Encoded in `/prune-branches`.
3. **Codify recurring procedures-with-a-gotcha as a dedicated
   micro-skill** surfaced by a one-line read-only hook — not AGENTS.md
   (kept sharply scoped) and not inlined into a deliberately
   conservative skill.
4. **When de-staling a docs index, verify each item against the repo
   before relabeling.** Second-domain genuinely shipped (data evidence);
   forecaster only partially (primitives, not inference); editor
   unverified → left as-is. Don't flip labels without evidence.
