## What happened

### 1. The rotation playbook, rehearsed before written

`knowledge/signing-key-rotation.md`: seven steps from keygen to
end-to-end proof. Every command was run against throwaway P-384 keys
before being written down (five runs: scalar always normalizes to 96
hex, both public-key derivations agree). The two rules the steps
encode are the inverse of the loss: nothing is deleted until its
replacement is verified by readback, and the secret moves only through
shell variables, never an interactive prompt. The loss itself is filed
in `knowledge/issues.md` with the `~/.zsh_history` evidence: the
placeholder `P@s5w0rd` typed at a bare `-w` prompt, and `rm key.pem`
riding the same paste, twice.

### 2. The rotation, and the wrong DNS panel

Steps 1 through 4 ran in-session: fresh key, scalar to keychain with
verified readback. The first operator DNS edit went to the Spaceship
panel and changed nothing, because Spaceship is only the registrar —
`dig +short NS untype.me` names Cloudflare's servers, and both
authoritative nameservers still served the old key. The publish
script's keychain-vs-record check refused exactly as designed. The
playbook's step 5 now checks the NS records instead of assuming a
host, and carries the registrar-is-not-the-DNS-host lesson (the SPF
record pointing at Spaceship email forwarding is what misled the
first draft).

The operator then re-ran the playbook end to end, minting a fresh key
of their own — which made the session's in-flight key obsolete without
ever being live, a harmless property of the playbook being
re-runnable. Completion was verified three ways before the temporary
PEM was deleted: keychain scalar, on-disk PEM and the authoritative
TXT record all derive the same public point, and `mcp-publisher login`
succeeded. The publish step then returned `400 "cannot publish
duplicate version"` with the card version unchanged — the expected
terminal state of a pure rotation, now recorded in step 7 with the
exact error text. The issues entry is marked resolved. The signing-key
item carried since session 59 is closed.

### 3. The unwrap sweep

Every tracked markdown file outside `plans/` and `sessions/` is now
soft-wrapped: one source line per paragraph and per list item. The
sweep covered 23 files (~1,500 joined lines) via a conservative
script that leaves fences, frontmatter, tables, headings, blockquotes
and explicit hard breaks alone; the diff contains zero fence-line
changes. The two `content/` files also carried hard-wrapped YAML
folded scalars; those collapsed to single-line quoted values, with
the parsed frontmatter verified deep-equal before and after. `data/`
claim files were already clean, so the content history has no
typography churn.

Verified with the project's own gate: prose-mint reports zero
hard-wrap findings across the swept files, other categories unchanged
or reduced (per-line hits merged), and the two residuals left standing
are judgement calls the prose rule explicitly allows — one-line
`spreadReadings:` values the detector pattern-matches as wraps. The
convention is codified in `.claude/rules/prose-style.md`: new docs
outside the two exempt trees are written soft-wrapped from the start.

## Decisions worth remembering

- **The registrar is not the DNS host.** `dig +short NS` before any
  DNS edit; the playbook now encodes the check. An edit saved in the
  wrong panel is inert rather than harmful, which is why the failure
  looked like propagation lag.
- **A re-runnable playbook makes in-flight state disposable.** The
  operator re-ran it and minted their own key; the session's key died
  unused and nothing broke, because every step verifies its own
  outcome rather than trusting the previous run's.
- **Playbook values stay generic.** The operator asked for the
  concrete steps added; they went in referencing "the line step 3
  printed" rather than the literal key value, which this very rotation
  made stale within a day.
- **Mechanical-sweep conflicts get mechanical resolutions.** Where a
  branch's only change to a file is a transform, resolve merge
  conflicts by taking the other side and re-running the transform,
  then verify the word stream matches. No hunk-by-hunk archaeology.
- **Use `git merge-tree --write-tree` for conflict probes.** The
  deprecated form piped through grep returned a confident false
  negative on a merge that conflicts.
- **The sweep's scope came from the gate's own config**, so
  "system-wide" has a checkable meaning: prose-mint scope minus the
  two trees whose `.prose-mint.toml` exempts hard-wrap.
