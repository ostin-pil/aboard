## What happened

### 1. Diagnosis

User reported, on `/graph` after `git pull --rebase`:

- Repeated `[React Flow]: Couldn't create edge for target handle id:
  "full-target", edge id: S3->M4#causes#1778882949251` (#008).
- `Parent node __domain_<domain> not found. Please make sure that parent
  nodes are in front of their child nodes in the nodes array.`
- Some nodes couldn't be dragged on the horizontal axis.

Read `persist.ts`, `engine-to-rf.ts`, `ClaimGraphRF.tsx`. Root causes:

1. **Dangling overlay handle.** The full-node drop zone (`a9a300b`)
   uses `id="full-target"`, a Handle that only mounts during a
   connection drag. `60d5302` normalized `full-*` → `null` in
   `onConnect`, but only for *new* connects. Edges created with the
   overlay between `a9a300b` and `60d5302` were already persisted into
   `aboard.graph.v3` with `targetHandle: "full-target"` and dangle on
   every load — nothing sanitizes persisted edges.
2. **Parent-after-child ordering.** React Flow requires a parent node to
   appear before its children in the nodes array. `bulkGroupInto`
   appended a newly synthesized domain group to the *end* of the array
   while its child claims (already earlier) carried `parentId` pointing
   at it. `savePersisted`/`hydrateFromPersisted` preserved that bad
   order, so the error recurred on every reload.
3. **Horizontal-drag pin = same root as (2).** When React Flow can't
   resolve a child's parent, `extent: 'parent'` can't compute a clamp
   box and the child is pinned. Inferred, not independently confirmed —
   shipped with a documented discriminating check + fallback (see
   Decisions).

Advisor confirmed (1)/(2), endorsed `types.ts` as the home for the
ordering helper, advised against pre-emptively inflating group widths
for (3), and recommended adding the ordering pass to `savePersisted`
too as a format invariant.

### 2. Fix (`3c6ff2b`)

- New `orderParentsFirst(nodes)` in `types.ts` — stable
  groups-then-claims. Claims' only parents are domain groups, so this
  satisfies React Flow's parent-before-child rule globally.
- Applied at three sites so the invariant is a property of the
  persisted format, not of each mutation site remembering it:
  `hydrateFromPersisted` (heals already-broken localStorage on load),
  `savePersisted` (defense-in-depth before serialize), and after
  `recomputeGroupBounds` in `bulkGroupInto`.
- New `cleanHandle()` in `persist.ts` drops any `full-*`
  `sourceHandle`/`targetHandle` during hydrate — self-heals existing
  localStorage on the next refresh, no manual clear required.

## Decisions worth remembering

1. **The persisted format owns the parent-before-child invariant.**
   Rather than fixing only the offending mutation (`bulkGroupInto`),
   `orderParentsFirst` runs on hydrate AND save AND after the mutation.
   A future "ungroup" / "move between groups" feature can't reintroduce
   the bug without going out of its way. Cheap (one filter pair),
   eliminates a class of error.
2. **Persisted state must be sanitized on load, not just on write.**
   The `full-target` bug shows write-time normalization (`60d5302`) is
   insufficient — anything already in localStorage from before a fix
   persists forever. Load-time `cleanHandle` is the durable fix and
   self-heals without a schema bump or user action.
3. **Issue 3 (horizontal drag) shipped on inference with a fallback.**
   High-confidence it shares root cause with the ordering bug
   (unresolved parent → `extent:'parent'` can't clamp). Did NOT inflate
   group widths pre-emptively — that would overlap adjacent domain
   groups (real regression) to fix a problem that likely won't exist
   post-ordering. Discriminating check handed to the user: if "parent
   not found" is gone but drag is still pinned, the one-line follow-up
   is `+ layout.colGap` slack in `recomputeGroupBounds`.
4. **No schema bump.** `cleanHandle` + reordering heal v3 data in place;
   bumping to v4 would needlessly discard the user's sandbox work.
   Consistent with the versioned-not-migrated stance (session 4 dec. 3)
   — but the lesson is that load-time healing beats a version bump when
   the data is salvageable.
