## Context

blocked on domain choice". The operator's first question was why a

That is an R-family defect in the sense `plans/audit-2026-08.md` uses
the term: a record that no longer tells the truth. It is also the
worst-behaved kind, because an index of open work is read as a to-do
list. A stale entry does not merely fail to inform, it actively
misdirects the next session, which is exactly what it did here.

## Decisions worth remembering

- **A plan file has to carry its own status.** Retiring the index row
  alone would have left `repo-hardening.md` still opening with "Blocked
  on: domain choice" for anyone who opened the file directly, which is
  how this session started. Each retired plan now leads with a Status
  block, and the index entry and the file agree.
- **The stale entry is the one that gets picked.** A plan index is read
  when choosing work, so its errors are selected for rather than merely
  tolerated. This session was routed into finished work by one line,
  and the routing is the cost, not the wrongness.
- **A reconciliation pass can write the record backwards.**
  `organic-traffic-dual-ux`'s Status was an explicit attempt to true
  the plan against the code, and it recorded §2 as declined two days
  after it shipped. Being reconciled once is not evidence of being
  correct.
- **Under-reporting and over-reporting are the same defect.** The plan
  index claimed unfinished work was pending; the funding checklist
  claimed finished work was pending. Both mislead the reader who is
  deciding what to do next.
- **`HANDOVER.md` was left alone on purpose.** Its open-work list is
  stale, but it is stamped point-in-time 2026-06-12 and directs the
  reader to `/session-start` for live state. Rewriting a dated snapshot
  destroys the record it exists to be; the fix for a stale snapshot is
  a newer one.
