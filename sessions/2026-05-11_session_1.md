### 7. Live Groq ensemble run on F2

Forecast F2 attaches to M3 (economic insecurity drives authoritarian
appeal). Question: will the OECD economic-insecurity composite
worsen for ≥50% of OECD countries between 2025 and 2028?

Providers configured (`providers.local.json`, gitignored):

| Name | Model | Family |
| --- | --- | --- |
| groq-llama-3.3-70b | `llama-3.3-70b-versatile` | Meta Llama 3 |
| groq-llama-4-scout | `meta-llama/llama-4-scout-17b-16e-instruct` | Meta Llama 4 |
| groq-qwen-3-32b | `qwen/qwen3-32b` | Alibaba Qwen |
| groq-gpt-oss-120b | `openai/gpt-oss-120b` | OpenAI OSS |

First pass: 2/4 succeeded.

| Model | Result |
| --- | --- |
| Llama 3.3 70b | P=0.42 |
| Llama 4 Scout | P=0.60 |
| Qwen 3 32b | FAIL — `<think>...</think>` reasoning tokens broke the JSON match |
| GPT-OSS 120b | FAIL — JSON truncated at position 1448 (max_tokens=800 too tight) |

Fixed:

- `parseRawPrediction` strips `<think>...</think>` blocks before
  searching for the JSON object.
- Replaced naive `{[\s\S]*}` regex with a `extractJsonObject`
  helper that walks brace depth (ignoring strings/escapes),
  collects every position where depth returns to 0, and tries
  each as the JSON close starting from the latest. On full
  failure, attempts a few common closers (`}`, `}]`, `]`) for
  truncation-tolerant repair.
- Default `maxTokens` raised from 800 to 1600 across all three
  adapters.

Second pass: 4/4 succeeded.

| Model | Probability |
| --- | --- |
| Claude (seed) | 0.55 |
| Llama 3.3 70b | 0.55 |
| Llama 4 Scout | 0.60 |
| Qwen 3 32b | 0.40 |
| GPT-OSS 120b | 0.32 |

Median 0.55, spread 0.28, range 0.32–0.60. The GPT-OSS reasoning
model is markedly more skeptical than the Llama family; Qwen sits
between. The Claude prior aligns with Llama 3.3 (RLHF-tuned mid-2024
architectures), with Llama 4 slightly above. This is the
disagreement signal the prototype is meant to measure.

The generated `baseRates` and `dataAnchors` came through structured.
Caveat flagged at end: the base-rate *questions* the models invent
are operationally soft (e.g. "How often have OECD countries
experienced year-over-year deterioration in economic insecurity
during periods of global economic slowdown?" without specifying
the comparison window). The shape works; the prompt could push
harder for narrow operationalized base rates on a future iteration.

## Decisions worth remembering

1. **Schema-before-data, data-before-UI within each phase.** Each phase's
   commits land in the same dependency order: types/schema, then data
   backfill, then UI. Keeps the build green between commits and gives
   the reviewer a clean reading order.
2. **Sequencing rationale honesty (advisor catch).** The plan originally
   said "D before E lets us learn from raw output what the structured
   shape should be." Advisor pointed out that's not actually true since
   D's prompt already produces a fixed shape; the real reason is "ship
   a working ensemble before fiddling with the schema again." Re-running
   F2 with the new prompt costs ~$0.01 so the redo is cheap. The plan
   file was updated to say so.
3. **Path (a) skeletal exporter (advisor catch).** The engine state
   doesn't carry DataPoints or enriched Source fields. Rather than
   extending the modal to capture them (Posture 3 territory), the PR
   pack emits *skeletal* claim files — basic sources, no DataPoints, no
   Analyses — and the PR reviewer adds the rich fields. The
   `PR-PACK-README.md` in each zip and the `/about#contributing` section
   both make this explicit ("the sandbox proposes skeletons; PR review
   adds evidence and analysis").
4. **Edge.sources moved into Phase A, not Phase C (advisor catch).** The
   original plan filed it as a Phase C addendum; A's schema-enrichment
   commit is the natural home.
5. **Native Anthropic adapter (advisor catch).** The original plan
   deprecated `generate-prediction.ts` without preserving the
   single-Claude path. Added `anthropic-native.ts` so existing
   Claude-authored predictions remain regeneratable via the new system.
6. **Ensemble re-runs are append-only.** `ensemble-predict.ts --update`
   appends; never overwrites. Audit trail of every model's output for a
   forecast stays intact across reruns and prompt iterations.
7. **One prompt for all providers.** Shared `FORECASTER_PROMPT` — not
   per-family tuning. Disagreement under identical input is exactly the
   signal the prototype wants to measure; per-family prompts would
   confound calibration variance with prompt variance.
8. **Median, not mean, as the headline.** Robust to one outlier model
   failing calibration entirely. Mean and full range are also surfaced
   so the spread isn't hidden.
9. **Domain chip filter (Option B), not color-coded borders (Option A).**
   User pick at planning time; confirmed Option B's clarity beats
   Option A's information density at 2-domain scale. Cluster-by-domain
   layout is deferred to v2 when a third domain lands.
10. **Approximate DataPoint values with `note: refresh on regeneration`.**
    Project rule: real sources only. Extended to DataPoints: values are
    public-domain ballparks (BLS 9.9% union density, WID 20.5% top-1%,
    ANES 22°F out-party thermometer) with notes flagging
    approximation. A future agent-regen pass against the canonical
    dataset can sharpen them.
