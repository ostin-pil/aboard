## Context

Follow-up to the session-10 collapsed-group work (merged via PRs #10/#11).
Browser verification of the `db43934` drag fix passed and surfaced two
collapse-behaviour issues the maintainer wanted addressed: (1) `reset`
left collapsed groups collapsed but a reload expanded them —
inconsistent; (2) collapsing a group hid *all* its edges, including
cross-domain connections, when those should stay visible. Both landed
as separate commits; both browser-confirmed.

## What happened

### 1. Verified the session-10 drag fix (carried empirical step)

`db43934` (collapsed pill stays draggable) confirmed in-browser across
all three scenarios — fresh collapse, after `reset`, after reload. This
closed the one open item from the session-10 log.

### 2. reset → expand; dropped the separate collapsed-id store (`6d30bc5`)

Maintainer's call (via AskUserQuestion): `reset` should return the
canonical seed fully expanded. Previously `reset` re-applied collapsed
state from a separate localStorage key (`aboard.graph.collapsedGroups.v1`)
while a cold reload ignored it — so a group stayed collapsed after reset
but expanded after the next reload.

Collapse state already round-trips through the main persisted graph
(`aboard.graph.v3`), so the separate key was redundant. Removed
`COLLAPSED_KEY`, `loadCollapsedIds`, `saveCollapsedIds`, and
`applyCollapsedState`; `clearPersisted` (and thus `reset`) now wipes
collapse state with the graph. Normal reload still restores collapse
from the main store. Net −104 lines. This also dissolved the
toggle/reset desync surface the `applyCollapsedState` "pure mirror" was
guarding — there's now a single collapse code path (the live toggle),
persisted verbatim.

### 3. Boundary edges stay visible on collapse (`07b9d58`)

Collapsing a domain used to hide every edge touching its claims. Now:

- **Internal** edges (both endpoints inside the group) → still hidden.
- **Boundary** edges (one endpoint outside) → re-pointed to the
  collapsed pill so the connection stays visible. The original child
  endpoint + handle is stashed in `edge.data.collapsedRemap` and
  restored on expand. Source and target are stashed independently, so an
  edge crossing two collapsed groups routes pill-to-pill and restores
  correctly as each group expands.

`DomainGroupNode` renders non-connectable target/source handles only
while collapsed (the pill's edge anchor); `updateNodeInternals` (already
called on collapse for the drag fix) re-measures them. Export paths
(`rfToEngine`, `exportClientJSONLD`) resolve canonical endpoints via a
new `canonicalEndpoints` helper so a pill id never leaks into JSON-LD or
the PR pack. Browser-confirmed: cross-domain edges CE1–CE3 stay visible
on collapse, route pill-to-pill when both domains collapse, and restore
on expand; export shows real claim ids.

## Decisions worth remembering

1. **`reset` discards collapse; collapse lives only in the main store.**
   The separate collapsed-id key was removed. One collapse code path (the
   live toggle), persisted verbatim through `aboard.graph.v3` — no
   "pure mirror" helper to keep in sync, so the toggle/reset desync
   class of bug is gone by construction.
2. **Collapsed group = edge anchor via handles rendered only when
   collapsed.** Boundary edges re-point to the pill; the pill's
   target/source handles are `isConnectable={false}` (display-only, no
   group-level connection semantics). `updateNodeInternals` re-measures
   them on collapse.
3. **Re-pointing mutates `edge.source/target`, which leaks to exports.**
   The fix stashes the real endpoint in `edge.data.collapsedRemap` and
   resolves it via `canonicalEndpoints` at every export site
   (`rfToEngine`, `exportClientJSONLD`). Add the resolver to any new edge
   export path.
