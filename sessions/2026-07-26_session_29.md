## What happened

### 1. Lint stopped seeing session worktrees (`384cb29`)

Building a comparison copy of `origin/main` in `.claude/worktrees/` made lint
report 15 problems instead of 14. `worktree_dir` is `.claude/worktrees`, which
`.claude/rules/workflow.md` tells every concurrent session to use, and ESLint
was walking it: a parked worktree is a second checkout of the same repo, so
every file gets reported twice and a warning in the other branch's tree can
fail the gate on work that is not being checked. Confirmed with a probe file
(one error appeared, then vanished after the ignore). Same root cause as
session 28's `.wrangler` ignore, one directory over.

### 2. Slice A: a constants module, built and superseded (`4a79e3d`, then `dbd69ce`)

`src/lib/copy.ts` exported the shared strings as typed constants, with a
`copy.test.ts` confining a distinctive fragment of each to that module, the way
`canonical-urls.test.ts` confines origin literals. It worked: output was
byte-identical to `origin/main` but for two intended reconciliations.

It was rejected on review anyway, and the reasoning is worth keeping. Prose
still lived in code, so the content was still a developer artifact. Worse, the
guard test pinned prose fragments in a test file, which made every copy edit
also a test edit. That is the wrong incentive for editorial text.

Two rules from the attempt survived into the replacement: prose carries no
markup that a call site could wrap around it instead, and copy that differs by
audience stays adjacent rather than being flattened into one string.

### 3. Slices B and C: prose as a loaded content tree (`dbd69ce`)

`content/site.md`, `content/home.md` and `content/about.md`, read by
`src/lib/content/`. Frontmatter is the metadata and the body is the prose,
mirroring `data/<domain>/claims/<id>.md`.

The module splits the way the Worker does, pure core plus thin IO shell:
`schema.ts`, `parse.ts`, `render.ts` and `spread.ts` are unit-testable under
the node-environment vitest config, and only `loader.ts` imports `server-only`.
`content.test.ts` checks the shipped documents against their schemas, so a
malformed document fails `npm test` rather than only `next build`.

Three problems the shape had to solve, none of them visible when the plan was
written:

- **Derived counts.** The about page interpolates claim, forecast and domain
  counts that session 26 deliberately made derived. `{{placeholder}}` tokens
  keep that; `interpolate` throws on an unknown token rather than shipping
  `{{clamCount}}` to a reader, and `vars.ts` feeds the page and the twin alike.
- **Blocks Markdown cannot express.** Module cards and reading cards stay
  frontmatter data, positioned by `<!-- slot: name -->` markers in the body. An
  HTML comment survives Markdown rendering unchanged, so the same splitter
  serves the page (components) and the twin (prose).
- **Where sections come from.** The page renders whatever the document's `##`
  headings are, keyed by slug, so adding or reordering a section is a content
  edit. Slugs became the anchor ids, which preserved `/about#contributing`.

`/about` gained the Markdown twin session 28 deliberately excluded, since
serving the body is no longer a hand copy of it. Slice C came along
uninvited: about 100 inline `style={}` objects cannot follow prose through a
renderer, so `about/page.tsx` went from 479 lines with 102 inline styles to 137
lines of chrome with none.

### 4. The spread table was not stale, it was wrong (`b0e7afd`)

The plan's leading follow-up was that the per-forecast spread table hardcoded
its numbers. Deriving them showed the duplication had already diverged:

| | published | actual |
| --- | --- | --- |
| F1 spread | 0.30 | 0.37 |
| F4 spread | 0.25 | 0.30 |
| F5 median | 0.40 | 0.30 |
| IF1 | absent | exists (single prediction) |

The claim detail pages compute the same statistics through `forecast.ts` and
were already showing the correct values, so `/claims/M2` and `/about`
contradicted each other in public.

`spread.ts` derives each row with `aggregate()` and keeps only the editorial
`reading` column authored, keyed by forecast id. It asserts in both
directions: an ensemble forecast with no reading fails, and a reading with no
forecast behind it fails. Verified by removing F3's reading and watching the
guard fire. Rows gate on more than one prediction, per `forecast.ts`'s
documented contract, which excludes `IF1`: a single-prediction forecast has a
spread of 0 by definition and would read as perfect consensus rather than as an
absent ensemble.

## Decisions worth remembering

- **Constants in TypeScript are not a content layer.** They keep prose in code
  and make copy edits into test edits. The content tree makes the
  single-source property structural, so the fragment-confinement test that
  slice A needed has nothing left to do and was deleted rather than ported.
- **`marked`, and no sanitizer.** One dependency with no transitive ones, and
  GFM tables came with it. Sanitization is deliberately absent because every
  document is authored in-repo, reviewed in a PR, and rendered at build time;
  the write path produces `data/` PRs, never site copy. Recorded in
  `render.ts` with the condition that reverses it: if editorial content ever
  becomes agent-writable, the sanitizer lands in the same commit that opens
  the path.
- **Only blocks Markdown genuinely cannot express earn a slot.** The two card
  grids did; the spread table did not, until it became derived and needed a
  component again. Tabular content is a GFM table.
- **Both directions of a data-to-copy mapping must assert.** `spread.ts` fails
  on a forecast with no reading and on a reading with no forecast. Asserting
  one direction only is how the table went stale in the first place.
- **Single-prediction forecasts are not ensembles.** Gating on more than one
  prediction follows `forecast.ts`'s documented contract and keeps `IF1` out
  of a table about disagreement between models.
- **Test structure, not prose.** The new suites assert what a page would crash
  on: a missing field, a slot with no component, an undefined placeholder, a
  reading with no forecast. A copy edit never touches a test.
