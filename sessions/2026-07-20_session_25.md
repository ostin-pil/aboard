### 2. Batch 2 implementation (PR #54)

Seven atomic commits, browser-verified:

- **N1 (new, MED)** client-only render. The graph is prerendered under
  `output:"export"` but its state comes from localStorage, so the server tree
  and the hydrating client disagreed on every load with a saved sandbox. Gated
  the canvas subtree on a mounted flag. Verified: the built HTML no longer
  contains the react-flow tree and the hydration error is gone.
- **E1 (HIGH)** inline isolation. The self-heal guard read
  `mode !== "fullbleed" || ...`, so inline was exempt from all validation and
  rendered a visitor's `/graph` sandbox on the landing page. It was
  bidirectional: injected group chevrons wrote back to the shared key. Inline
  now builds fresh from `data/`. Verified with a 26-node sandbox seeded: `/`
  showed the canonical 12-node view and the cross-domain `error#008` warnings
  disappeared.
- **N2 (new, LOW)** reject stringified `"null"`/`"undefined"` handles in
  `cleanHandle`, the direct cause of the observed React Flow error #008.
- **E2 + E3 (MED)** validate and version the persisted payload. Zod validation
  replaces the old truthiness checks that inspected only `nodes[0]` and never
  `edges` (so a corrupt payload threw in the render-phase hydrate and
  white-screened the route). A `schemaVersion` drops incompatible payloads
  silently; a content `seedHash` over the canonical claims' `id:kind` detects
  `data/` drift without a manual bump, keeps the edits, and shows a "reset to
  rebuild" notice. 17 new unit tests with an in-memory localStorage stub.
- **E4 (MED, elevated)** replay collapse post-processing on undo/redo. Undo of
  a collapse skipped the re-measure and bounds-recompute the live path runs, so
  the group wedged (pill undraggable, expand chevron unhittable). Routed both
  through a `restoreSnapshot` helper. Verified via the graph instance: undo
  restored the full 912x704 box (not a stale 220x56), redo re-collapsed
  cleanly, and the chevron stayed responsive through the cycle.
- **Error boundary** `src/app/graph/error.tsx`, the safety net when validation
  is bypassed; clears the sandbox and retries. Uses this Next version's
  `unstable_retry` prop, not the older `reset`, confirmed against the bundled
  docs.

Closed the `knowledge/issues.md` 2026-05-20 localStorage-staleness entry:
options 2 to 4 from its ranked list all landed here, and the re-audit found
option 1's inline exemption was the E1 bug.

## Decisions worth remembering

- **Read the code, not the audit report.** The re-read against `main` found E1
  was bidirectional (not a stale read), surfaced N1 (SSR hydration mismatch)
  and N2 (the literal `"null"` handle), and caught that this Next version's
  error boundary uses `unstable_retry`, not `reset`. None of these were in the
  audit.
- **Dark Reader confounds visual QA.** The extension recolored graph node fills
  to near-black (`#181a1b`), making the canvas look empty though the nodes
  rendered fine. Chased it briefly before spotting the signature. Verify
  through the DOM and console, not screenshots, when an extension is active;
  run visual checks in an extension-free window. (Also a possible real-user
  concern, pre-existing, out of scope here.)
- **Verify interaction bugs behaviorally, not by pixels.** E4's wedge lives in
  React Flow's measurement cache, invisible to unit tests and to a screenshot.
  Drove undo/redo through the graph instance and read the resulting box
  dimensions, which is both Dark-Reader-immune and precise.
- **E2 and E3 are one commit, not two.** They share the payload schema, the
  `loadPersisted` signature, and the threading; splitting them would be
  contrived.
