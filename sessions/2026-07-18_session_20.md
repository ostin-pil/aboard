### 3. `propose_dossier` (#42) — the last tool, reframed

The plan's `propose_dossier_position` doesn't fit the data model: a dossier
requires both a pro and a con side, so a single-position proposal can neither
form a valid dossier nor fill a "missing" side (dossiers are never partial), and
overwriting a curated side is destructive. Reframed (with the maintainer's
agreement) to propose a **complete dual-dossier** for a claim that lacks one:
both steel-manned sides plus optional ranked cruxes, `authoredBy` stamped on
each, refusing an unknown claim or an existing dossier. Verified live: PR #43, a
real dual-dossier on `IM1` (Piketty's r > g vs the Rognlie / Acemoglu-Robinson
critique).

Wiring the last tool removed the MCP server's `notWired` dead code; all surface
docs now say four live tools.

## The recurring lesson, again

Live testing kept catching what unit tests missed, because the tests kept
encoding the wrong contract:

- `propose_edge` (session 19): rationale required in the payload, which the
  client strips — every edge 422'd.
- `propose_forecast_prediction`: the fixture used short strings, so it missed
  that `lineWidth: 0` reformats folded files.

Each fix added a test that mirrors the real seam. The pattern is clear: a unit
test that doesn't exercise the exact shape the Worker produces will pass while
the live path fails.

## Decisions worth remembering

- **Match the file's own serialization style.** New content (claim, edge) uses
  `lineWidth: 0`; appending to existing files (prediction, dossier) uses the
  default folding those files were written with, or the diff becomes a full
  reformat. The reviewability of the human-gated model depends on minimal diffs.
- **Reframe a tool to fit the data model, don't force it.** A dossier is
  inherently two-sided; the single-position framing was a plan artifact, not a
  requirement.
- **The write path is now the thesis, demonstrated.** The graph contains a
  claim, an edge, a prediction, and a dossier filed by an agent through the
  gated, provenance-stamped, human-reviewed path.
