## Decisions worth remembering

- **Plain node beat pool-workers on the merits, not on compatibility.**
  The probe passed, so the decision could not hide behind "the pool
  does not support vitest 4". What decided it: the tests' seams are
  injected either way, and a harness buys fidelity only for surface the
  code actually uses. The revisit trigger is named in the config.
- **A parity test across a dependency-major boundary wants each side's
  own resolution, asserted.** Placement in `mcp-server/` makes import
  resolution do the work; the explicit zod-path assertion is what stops
  a missing install from silently collapsing both sides onto one major.
- **The telemetry question is now answerable on demand, and worth
  re-asking before posting.** The recurring caller strengthens the
  launch post's usage line; the query took one keychain read.
- **Suspicion of an easy pass is warranted but answerable.** The parity
  suite passed first try; the surfaces really are aligned today. The
  test count arithmetic (648 + 41 = 689) is the cheap check that the
  new suites actually ran.
