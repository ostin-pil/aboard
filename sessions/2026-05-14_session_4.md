# Session 4 — 2026-05-14

Branch: `feature/session-4-react-flow`

## Context

Session 4 implemented the engine migration from vanilla JS to React Flow
that was scoped during session 3. User questioned the planned React Flow
choice on two grounds — possible pro-gating of features, and performance
concerns — which prompted a research-driven evaluation against Cytoscape,
Reaflow, Rete, and the alternative of stabilizing the vanilla engine in
place. Both stated concerns dissolved under primary research (no library
features are paywalled; performance has ~2 orders of magnitude of
headroom for aboard's scale). The real decision became "migrate now vs
stabilize vanilla," not "which library." Migrate won. After the migration
landed, two follow-up rounds added perf optimizations (viewport culling,
drag transition gate, LOD via useStore) and three richer-editor features
(multi-select + delete, domain-based grouping with collapse/expand).

## What happened

### 1. Research + reframe of the decision

Read the awesome-node-based-uis list and verified the candidates from
primary sources. Findings:

- **React Flow Pro** gates only examples, templates, attribution removal,
  and 1:1 support. Every API in `@xyflow/react` is MIT. Attribution
  removal is legally permitted under MIT (the docs ask for sponsorship
  if commercial, but that's not a license condition).
- **Performance**: 100 *heavy* nodes at 35–40 FPS dragging, stable 60 FPS
  otherwise. aboard runs ~20 nodes today, plausibly low-hundreds
  long-term. Real degradation kicks in at 1k+ with non-memoized customs
  — both fixable, neither relevant.
- **Reaflow**: similar DOM-based architecture, 10× smaller community
  (2.5k vs 30k+ stars), no architectural advantage. Distant third.
- **Cytoscape.js / sigma.js**: canvas/WebGL, scales to 10k+ nodes with
  built-in graph algorithms — wrong shape for our DOM-based rationale
  popover, and we don't need their scale.
- **Rete.js**: visual-programming dataflow with sockets — wrong domain;
  our edges are causal claims, not dataflow connections.

Advisor catch reframed the presentation: the user's concerns don't
discriminate between options. The actual choice was "migrate now (~1
session, replaces 985 LOC of hand-rolled drag/zoom/popover) vs stabilize
vanilla (~0.5 session, preserves the just-stabilized engine but owns it
forever)." User picked migrate. Plan file rewritten with the comparison
and recommendation, then ExitPlanMode approved.

### 3. Perf fixes (commit `53c58c6`)

User opened `/graph`, reported sluggish drag at 40% zoom and unreadable
text still being rendered. Three fixes:

- **`onlyRenderVisibleElements={true}`** on `<ReactFlow>` — viewport
  culling. Known issue #4516 about offscreen-edges-not-rendering was
  reviewed, judged not relevant to our tightly-clustered layout (and
  user confirmed it looks old/likely fixed).
- **Hover transition gated to `.react-flow__node:not(.dragging)`** and
  cleared during `.dragging`. Cursor crossing nodes during drag no
  longer triggers per-node `box-shadow` + `transform` repaints.
- **LOD pattern in `ClaimNode`**: `useStore((s) => s.transform[2])` reads
  the live zoom; below 0.6 the node renders only `KIND · ID`, dropping
  title, body, badges, and the edit button from the DOM. Same pattern as
  React Flow's `contextual-zoom` example. New `.ag-node-lod` style
  shrinks the pill.

### 4. Multi-select + multi-delete (commit `6df5cda`)

React Flow already supports Shift+drag (box) and Cmd/Ctrl+click
(additive) by default — wired explicitly + made discoverable.

- `selectionKeyCode="Shift"`, `multiSelectionKeyCode={["Meta","Control"]}`
  — defaults made explicit in code.
- `deleteKeyCode={["Backspace","Delete"]}` + `onNodesDelete` /
  `onEdgesDelete` wired to snapshot+persist+cascade-delete-edges-on-
  node-delete. Backspace on selected nodes removes them and the edges
  touching them, with undo support.
- Bottom-right Panel in editor mode shows the affordances:
  `⇧+drag box-select · ⌘+click add · ⌫ delete`.
- Per user note (working on touchpad), `selectionOnDrag` deliberately
  NOT enabled — modifier keys required so drag still pans.

### 5. Domain grouping + collapse/expand (commit `c8e9ccd`)

Each domain becomes a labeled parent group containing its claims.

- New `DomainGroupNode` (non-interactive, `selectable: false`,
  `focusable: false`, `zIndex: -1`) — dashed rectangle by default with
  a header containing `−`/`+` toggle, label, and claim count.
- `types.ts`: `GraphNode = ClaimNode | DomainGroupNode` union with
  `isClaimNode` / `isGroupNode` type guards. Type guards added in every
  helper that previously assumed `ClaimNode` (`newId`,
  `existingRowsCount`, `isNeighbor`, `onConnect`, `onNodesDelete`,
  `exportJSONLD`).
- `engine-to-rf.ts`: layout reworked. Groups emitted only in `fullbleed`
  mode. Children get `parentId` + `extent: 'parent'`. Multiple domain
  groups stack horizontally with 80px gap. Inline (landing) mode keeps
  the prior absolute-positioned layout — single-domain context, group
  container would be visual noise.
- `ClaimGraphRF.toggleDomainCollapse`: walks children + intra-group
  edges to set `hidden`. Collapsed group shrinks to 220×56 pill, child
  nodes + edges-touching-children hide.
- `persist.ts`: discriminated schema with `kind: "claim" | "domainGroup"`.
  Key bumped to `aboard.graph.v2` so the prior v1 hydrate falls through
  to fresh layout.
- Group nodes are unselectable so multi-select + Backspace can never
  pick or delete a whole domain.

## Decisions worth remembering

1. **Both user concerns dissolved under research, but the decision still
   mattered.** Pro-gating: zero library features paywalled. Performance:
   ~2 orders of magnitude headroom for aboard's scale. Real reframe:
   "migrate now vs stabilize vanilla." Picked migrate to get off the
   maintenance escalator before methodology-first features add more UI
   weight on top of the engine.
2. **Reused `.ag-*` CSS visual styles, dropped the structural ones.**
   Custom node renders the same DOM shape as the vanilla `.ag-node`
   (meta + title + badges + edit btn), so 80% of the design CSS carried
   over. Replaced `position: absolute` + viewport/canvas/stage rules
   with React-Flow-aware sizing on `.react-flow__node-claim` +
   `.ag-rf-root` ancestors.
3. **localStorage versioned, not migrated.** v0 (vanilla) → v1 (post-
   migration) → v2 (post-grouping discriminated schema). Each schema
   change bumps the key. Old keys are dead data; the app isn't deployed,
   no migration logic to maintain.
4. **Hand-rolled undo/redo, not `zundo`.** zundo is a Zustand middleware;
   we don't use Zustand and the snapshot ring-buffer logic is ~30
   lines. Two libraries to save 30 lines isn't worth the dep weight.
5. **Inline (landing) keeps the old layout shape; only fullbleed gets
   groups.** Inline is always single-domain (filtered upstream in
   `page.tsx`) — group container would be visual noise. Fullbleed shows
   all domains in their own labeled containers.
6. **Group nodes are non-selectable.** `selectable: false` +
   `focusable: false` + `zIndex: -1`. Multi-select + Backspace can never
   accidentally pick a whole domain. Collapse is the only group-level
   interaction.
7. **LOD threshold at 0.6 zoom, not lower.** At 0.6 the title text is
   ~7-8px on a 240px-wide card — partially readable but degrading.
   Below that we drop to kind + id only. Above that, full content.
   Chosen by visual judgment; could be tuned with a measurement pass.
8. **`selectionOnDrag` deliberately NOT enabled.** User on touchpad —
   Figma-style drag-to-select would conflict with pan. Multi-select
   stays modifier-keyed (Shift box, Cmd/Ctrl additive).
