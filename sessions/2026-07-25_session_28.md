## Context

Session 27's isitagentready re-scan left one cheap point on the table: the
Content category, 0/1, failing Markdown negotiation. Cloudflare sells that as
a Pro-plan feature ("Markdown for Agents"), but aboard did not need to buy it.
The per-claim Markdown twins already existed from slice 1 and every request
already passes through our own Worker, so the Worker could answer
`Accept: text/markdown` itself. This session implemented that, then wrote up
the architectural question it surfaced.

## What happened

### 1. Markdown content negotiation (`3ecace2`)

An agent sending `Accept: text/markdown` to a page URL now gets that page's
Markdown twin, so it does not need to know the `/index.md` convention to get
Markdown out of a link it was handed.

- `src/lib/markdown-negotiation.ts` — `prefersMarkdown` (RFC 9110 q-value
  precedence, exact range beating subtype wildcard beating the bare wildcard)
  and `markdownTwinPath`. Pure, so the Worker stays the thin shell its module
  header promises.
- `src/lib/markdown-negotiation.test.ts` — 15 tests covering real browser and
  curl headers, q-value ties, wildcard-only clients, and the path refusals.
- `src/app/index.md/route.ts` — homepage twin, every count derived from the
  graph.
- `src/app/dossiers/[claimId]/index.md/route.ts` — 3 dossier twins, cruxes
  ranked by impact times uncertainty exactly as the page ranks them.
- `worker/index.ts` — negotiation ahead of the asset fall-through.
- `wrangler.jsonc` — `assets.run_worker_first` for the negotiable routes.
- `public/_headers`, `/llms.txt`, `/about` — `Vary: Accept` and the copy that
  advertises the behaviour.

Verified against `wrangler dev`, not just the build. Markdown for `/`,
`/claims/S1` and `/dossiers/M4`; HTML preserved for `*/*`, for Chrome's real
Accept header, and for `text/markdown;q=0.4, text/html`; `/graph` falls through
because it has no twin; `/api/graph` and `/robots.txt` untouched; HEAD works;
POST does not negotiate.

### 2. The bug that was invisible in code review

The first implementation returned HTML for every probe. **Static assets are
served before the Worker runs**, so a request for `/` never reached the
handler at all. The fix is `assets.run_worker_first` in `wrangler.jsonc`,
scoped to `["/", "/claims/*", "/dossiers/*"]` rather than `true` so JS chunks
and JSON-LD assets keep being served with no Worker invocation. The config key
came from the Cloudflare docs rather than a guess, then was confirmed against
the local runtime.

Worth recording because the code was correct and simply never executed. No
amount of reading `worker/index.ts` would have found it; only running it did.

### 3. Lint baseline restored (`5beed13`)

Lint read 186 warnings against session 26's documented 14. 172 came from
`.wrangler/tmp/` Worker bundles that `wrangler dev` generates, which ESLint
was walking because its ignores cover `.next`, `out` and `build` but not

### 4. Plan: editorial prose as content data (`3ce2756`)

The `/about` twin was deliberately skipped (its prose is hand-written in TSX,
so a twin would be a hand copy). That prompted the question of why the site's
prose lives in `.tsx` at all, and a measurement pass turned up the answer's
evidence:

- The positioning paragraph exists **five times** (`layout.tsx`, `page.tsx`,
  `about/page.tsx`, `llms.txt/route.ts`, and `index.md/route.ts` added this
  session, reworded and reflowed so it no longer matches the other four even
  as a substring).
- `about/page.tsx` is 479 lines with 102 inline `style={}` objects, breaking
  both CLAUDE.md's ~250-line page rule and the class-based system in
  `globals.css` (446 classes) that `claims/[id]/page.tsx` already follows.

`plans/content-as-data.md` splits that into three independent slices (one
copy module; a `content/` tree with a renderer; inline styles to classes),
records the decisions to make first, and states what not to do: the
data-driven pages stay React over Zod-validated types. Indexed in
`plans/README.md`.

## Decisions worth remembering

- **`run_worker_first` scoped to routes, not `true`.** Every request in the
  list costs a Worker invocation, so listing `/`, `/claims/*` and
  `/dossiers/*` keeps the static chunks, images and JSON-LD on the free asset
  path. The tradeoff is that a future negotiable route has to be added here
  too, which is why the wrangler comment says so.
- **The Markdown branch sends `Cache-Control: no-store`.** `Vary: Accept` is
  declared on the HTML side for correctness, but Cloudflare's edge cache keys
  on Accept-Encoding rather than Accept, so `Vary` alone would let a cached
  Markdown response reach the next browser asking that URL for HTML. Twins are
  cheap to regenerate; a page served as raw Markdown to a human is not cheap.
- **HTML stays the default unless `text/markdown` is named explicitly.** A
  bare wildcard scores Markdown and HTML equally, and `*/*` is what curl and
  naive clients send. An explicit-mention requirement is what keeps them on
  HTML. A genuine tie between explicit `text/markdown` and `text/html`
  resolves to Markdown.
- **`/about` and `/graph` have no twins, deliberately.** `/about` is
  hand-written prose (a twin would be a hand copy, which is the drift
  `plans/content-as-data.md` addresses) and `/graph` is an interactive canvas.
  Both fall through to HTML, which is what negotiation should do when a
  representation does not exist.
- **Twin existence is answered by the asset lookup, not a list.** Adding a
  twin route is all it takes to make that page negotiate, which is why the
  `/about` twin needs no Worker change when slice B of the plan lands.
- **Claim bodies are plain prose today**, so rendering `claim.statement` as
  raw text is not a live defect. It becomes one when someone writes a list
  into a claim body. Recorded in the plan, not fixed here.
