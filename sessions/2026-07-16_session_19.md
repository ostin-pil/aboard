## What happened

### 1. The pure core — buildEdge + appendEdgeToYaml (`8f80735`)

`src/lib/proposals.ts`:
- `EdgePayload` — from, to, kind, strength, rationale (required — an unexplained
  relation is not reviewable), sources (optional, like the seed edges). No id:
  the server mints it.
- `nextSequentialId(stem, ids)` — extracted from the claim minter, now shared.
  Anchored, so stem `E` does not swallow `IE7` or `CE1`.
- `buildEdge` — validates both endpoints exist, refuses a self-loop, and routes
  by scope: an **intra-domain** edge lands in that domain's `edges.yaml` with an
  id on the domain's own prefix (`E` / `IE` / `ECE`); a **cross-domain** edge
  lands in `cross_domain_edges.yaml` with a `CE` id. The prefix is read off the
  domain's existing claims, the same convention-from-data approach as claims.

`src/lib/data/serialize.ts`:
- `appendEdgeToYaml(existing, edge)` — adds the edge as one list item to the
  file's existing content, preserved verbatim, so the PR diff is exactly the
  lines added rather than a reformat of every entry. Empty / `[]` files start a
  fresh list. Drops an empty `sources: []` line so rationale-only edges match the
  hand-authored style.

### 2. Tests, mutation-checked

17 new unit tests (66 total): edge routing and id minting for all three intra
prefixes plus cross-domain, self-loop and unknown-endpoint refusals, and
`appendEdgeToYaml` round-tripping through the YAML parser and the `Edge` schema.
Mutation check: forcing every edge intra-domain (`crossDomain = false`) turns the
cross-domain routing test red, then restored.

### 3. The Worker — append-to-existing-file

`worker/index.ts` gained an edge branch and a real refactor. The GitHub plumbing
is now reusable pieces (`getFile` returning content + sha, `submitProposalPR`
taking an optional sha → update vs create) shared by both proposal kinds. The
edge handler reads the target file, appends, and commits with its sha; if the
file is absent it creates it. The success response is now `{ kind, id, ... }` for
both tools.

### 4. MCP + docs

`propose_edge` in `mcp-server` now POSTs to the endpoint (both write tools share
one `fileProposal` helper). `README.md`, `CONTRIBUTING.md` predecessors,
`worker/README.md`, `mcp-server/README.md`, and the plan banner all now say edge
is live.

## Decisions worth remembering

- **Minimal diffs on shared files.** An edge re-serialized through the whole list
  would reformat every existing entry and bury the one-line change. Appending the
  new item to preserved content keeps the PR reviewable — which is the point of
  the human-gated model.
- **Refuse rather than guess, again.** Self-loops and unknown endpoints are hard
  errors; a domain with no claims cannot receive an intra-domain edge id.
- **Edges have no attribution field.** Unlike claims, the `Edge` schema carries no
  `authoredBy`. The PR (branch name + provenance block) is the provenance. Not a
  gap to paper over by adding a field this session — a schema change with ripple,
  out of scope.
