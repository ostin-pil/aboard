### 2. Qwen unclosed-`<think>` fix + reasoning-model maxTokens

The session 1 strip handled `<think>...</think>` blocks closed before the
JSON. The new failure mode: Qwen 3 consumes the entire 1600-token budget
inside `<think>...` without ever closing the tag or emitting JSON. The
strip regex requires a closing tag, so the body retained reasoning text and
`extractJsonObject` returned null with a confusing error.

Two-pronged response in `scripts/forecasters/`:

- `prompt.ts` `parseRawPrediction`: after the normal closed-block strip,
  also locate any *unclosed* `<think>` and drop everything from there to
  the end of the string. Recovery isn't possible (the model never produced
  JSON), but the failure message no longer dumps reasoning content.
- `providers.local.json` (gitignored): per-provider `maxTokens: 3200`
  override on the Qwen entry so the reasoning trace has room to finish
  followed by the JSON object.
- `README.md`: corrected the stale `default 800` note (real default is
  1600) and documented the reasoning-model recommendation (~3200 for Qwen3,
  DeepSeek-R1, and similar).

### 6. Popover bug fixes (advisor catches)

Pre-implementation advisor pass found three issues:

1. **Hit-zone paths leaked on re-render.** `render()` removed `path.ag-edge`
   but not `path.ag-edge-hit`, so each edit-mode re-render stacked stale
   hit paths with stale event closures. Fix: broaden the cleanup selector
   to `path.ag-edge, path.ag-edge-hit`.
2. **Hit path swallowed edit-mode edge click.** The hit path is appended
   after the visible path and captures `pointer-events: stroke`. With the
   `openEdgeEditor` click handler attached only to the visible path, the
   editor never opened on edges with rationale (which is all of them).
   Fix: when `editable`, attach the same click handler to the hit path.
3. **Popover anchor was wrong for long diagonal edges.**
   `path.getBoundingClientRect()` returns the entire path's bounding box,
   so on a diagonal edge the popover landed far from the cursor. Fix:
   when the trigger is a `<path>`, anchor to `ev.clientX/clientY`; when
   it's the small label div, keep the bounding-rect anchor.

All three landed in one fix commit before the user opened the page.

### 7. Browser-reported issues — render-loop crash

User reported `Maximum update depth exceeded` originating at
`ClaimGraphCanvas.tsx:56` (`setReady(true)`) and `GraphFullbleed.tsx:27`
(`onZoom = (s) => setZoom(...)`). Diagnosed: the `useEffect` deps array in
`ClaimGraphCanvas` included `onPersist`, `onZoom`, `onReady`. Those are
inline arrows in `GraphFullbleed`, so they get fresh identities on every
parent render. Engine mount fires `onZoom` during initial layout →
`setZoom` → parent re-render → new callback identities → effect re-runs →
re-mount → loop.

Fix: stash the three callbacks in refs (`onPersistRef`/`onZoomRef`/
`onReadyRef`), assign the latest on every render, call `.current` from
inside the effect. Effect deps simplified to `[mode, editable, data]`.
Removed the unused `setReady` state at the same time (it had been a
leftover; no consumer).

The loop was also masking edge hover — listeners were attached, then
torn down on the next re-mount before they could fire. User confirmed
hover works after the fix.

### 8. Packed graph — inline filter + dynamic canvasW

User screenshot showed the landing inline graph cramming 20 nodes from two
domains into a 1180px canvas with `nodeW=188`, producing ~75px overlap on
the 8-mechanism row. The landing header already advertised "domain/
democratic_backsliding" — content didn't match the label.

Two changes:

- `src/lib/engine-adapter.ts`: `toEngineData` accepts an optional
  `{ domain }` filter; filters claims, edges (both endpoints must be
  included), and the returned `domains`/`domain` reflect the filter.
- `src/app/page.tsx`: passes `{ domain: "democratic_backsliding" }`.
  Inline graph is now 12 nodes, fits the canvas with the existing widths.
  Page stats (chip counts) deliberately left unfiltered — they reflect
  the corpus, the inline graph shows the primary-domain slice.
- `public/graph-engine.js`: `canvasW` is now `max(minCanvasW, padL + padR +
  nodeW + (maxRow - 1) * (nodeW + minGap))`. For sparse rows the existing
  `1180`/`1520` floors apply; for dense rows (e.g. fullbleed "all
  domains" with 8 mechanisms) the canvas widens. Fullbleed already has
  pan, so the wider canvas works without additional UI affordance.

### 9. Node-drag TypeError — capture element before async handlers

After the render-loop fix stabilized the engine mount, the user tried to
drag a node and got two errors:

```
graph-engine.js:646  Cannot read properties of null (reading 'style')
graph-engine.js:652  Cannot read properties of null (reading 'removeEventListener')
```

Root cause: `onNodePointerDown` captured the initial pointer event in `e`
and referenced `e.currentTarget` inside async `onMove`/`onUp` closures.
Browsers null `event.currentTarget` once dispatch completes, so the later
listeners see `null`. A latent bug — previously masked because the
re-mount loop was tearing down every drag before it could fail.

Fix: `const el = e.currentTarget` at the top of `onNodePointerDown`, use
`el` everywhere afterward. `onConnectStart` uses `document` as the
listener host and never reads `e.currentTarget` later, so no parallel
change needed there. User confirmed dragging works.

## Decisions worth remembering

1. **Spread varies meaningfully across questions.** Session 1's reading was
   that the F2 spread (0.28) might be the reliable story. Five forecasts
   later, spread ranges 0.10–0.30 depending on the question's
   measurement domain. The prototype's pitch shifts from "models disagree"
   to "*which* questions surface disagreement" — a stronger and more
   honest framing.
2. **F4 reading reversed once the 4th model joined.** With three models,
   F4 looked like a 0.40 consensus (spread 0.02). With Qwen included,
   spread is 0.25. Small ensembles can produce false consensus; this is a
   real lesson worth showing on the demo.
3. **Qwen-only retry, not full re-run.** Append-only semantics make a full
   re-run cheap audit-wise but inflate prediction counts and dilute the
   median. After the maxTokens fix, ran `--providers groq-qwen-3-32b
   --update` on F4 and F5 to add exactly the missing model. Cleaner data.
4. **Skeletal source-kind normalization rather than schema flexibility.**
   Considered making the loader Zod schema tolerate unknown `kind` values
   (e.g. via `z.union` + transform). Rejected: the published v0 JSON-LD
   spec lists the enum explicitly, so the loader should stay strict.
   Defense lives at the script layer (`normalizeSource`) where bad data
   never reaches disk.
5. **Stashing callbacks in refs over `useCallback` for the engine bridge.**
   Could have asked the parent (`GraphFullbleed`) to memoize each callback
   with `useCallback([])`. That works but requires every future consumer
   to remember it, and one missed memoization re-introduces the loop.
   Ref-stashing inside `ClaimGraphCanvas` makes the consumer contract
   robust to any callback identity churn from any parent.
6. **Inline filter, not "pan the inline view".** The landing graph
   advertises a single domain in its header; the simplest fix matches
   content to label. Pan on an inline thumbnail would have demanded new
   UI affordance and competed with page scroll. Fullbleed already has
   pan for the multi-domain case.
7. **One popover element per role, not a single shared popover.** Node
   popover stays click-pinned for the existing UX; edge popover is
   hover-only with a grace period. Sharing one element would cause edge
   hover to clobber click-pinned node content. Two elements, two roles,
   no state-tracking required.
8. **Advisor-then-implement, not implement-then-advisor.** The popover
   work got the advisor pass before the user saw it in a browser; all
   three caught issues (hit-zone cleanup, edit click, cursor anchor)
   would have been visible regressions otherwise. Worth repeating for
   non-trivial engine work.
