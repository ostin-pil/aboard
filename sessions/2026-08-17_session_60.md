## What happened

### 1. The event shapes, as a pure module

`src/lib/telemetry.ts` follows `rate-limit.ts` in every particular: the
binding is modelled as an interface rather than an imported Cloudflare
type, the sink fails OPEN (unbound or throwing means the row is lost and
the response is not), and the module is pure so vitest can reach it —
`worker/` sits outside the suite's include, which is the same reason S2's
cap went into `src/lib/proposals.ts` in session 59.

Three events, one `writeDataPoint` each. The event kind goes in the single
index Analytics Engine allows, which is also its sampling key, so a burst
of one event kind cannot thin the others' rows. Eleven unit tests cover
the outcome classes and the fail-open contract.

### 2. The Worker wiring

- `proposal` records at `runProposal` (wrapped around the now-inner
  `proposalResponse`), so an MCP write and an HTTP write are the same
  write in the telemetry too, distinguished by the `via` blob. Outcome is
  a closed five-class fold of the status code: accepted, unauthorized,
  rate_limited, rejected, failed.
- `mcp_call` records in `handleMcp` once a message resolves to a
  `tools/call`, before authorization, so a rejected write still registers
  as usage. The who-dimension is credential presence, not validity:
  resolving a credential to label a row would put a KV lookup on the
  anonymous read path, which deliberately touches no storage.
- `twin` records the pathname a Markdown twin was served for, bounded by
  the corpus.
- `Env` gains `EVENTS?: AnalyticsDataset`, optional for the limiter's
  reason: a deploy without the binding stays whole.

### 3. The config, and the pin it turned out to need

`wrangler.jsonc` gains the `EVENTS` → `aboard_events` dataset binding
(nothing to provision; the dataset is created by the first write) and the
`observability` block at `head_sampling_rate: 1` — at this Worker's
volumes the free allowance is not a constraint, and a sampled-away error
is the expensive kind. The 500 path returns a deliberately generic body
since S5, so the platform log is where an exception gets diagnosed.

The plan said extend `config-lint` only if the binding needs pinning. It
does: `record` fails open by design, so renaming the binding, the dataset
or the `Env` field errors nowhere at runtime — the rows just stop, which
is the one failure telemetry cannot report about itself. `ANALYTICS_MIRROR`
in `src/lib/config-lint.ts` now holds all three names against
`wrangler.jsonc` and `worker/index.ts`, with the dataset pinned because
`worker/README.md` queries it by name and a rename would answer "no
traffic" from an empty table. All three faults were planted and caught
before the check was trusted, each finding naming the file and the
consequence.

### 4. The how-to-query note

`worker/README.md` gains a Telemetry section between Rate limiting and the
MCP endpoint: the row schema, the two honest bounds (presence-not-validity,
and an MCP write counting once per door and once per decision), the SQL API
query for "did anyone call the API this week" written with
`SUM(_sample_interval)` so it stays correct when sampling starts, and the
verified numbers: three-month retention, 100,000 points written and 10,000
SQL reads per day on Workers Free, 3-day log retention.

## Decisions worth remembering

- **The pure module again, for the third time.** `spread.ts` argued it,
  `superseded.ts` followed it, S2's cap confirmed it: logic the Worker
  needs goes in `src/lib/` because that is where the tests can see it.
  `telemetry.ts` did not re-decide this, it applied it.
- **Fail-open telemetry is why the pin exists.** A gate for a fault class
  was added in the same commit that created the class: once `record`
  swallows every failure, no runtime signal distinguishes "no traffic"
  from "binding renamed", so the only honest reader is a config check.
  Planted three ways before being believed.
- **Presence, not validity.** The `mcp_call` who-dimension could have been
  exact by resolving the credential, at the price of a KV lookup on every
  anonymous read — ending a property `wrangler.jsonc` documents. Telemetry
  does not get to change the hot path it observes.
- **Count before authorization.** A rejected write is usage; recording
  after the auth gate would have made abuse invisible in the one place
  built to measure interest.
- **Docs numbers are fetched, not remembered.** Retention, allowances and
  the writeDataPoint limits all came from live Cloudflare pages; the
  config shapes came from wrangler@4's own schema. Two of the numbers
  (blob budget, logs retention) differed from what memory would have
  written.
