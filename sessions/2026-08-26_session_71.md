## What happened

### 1. The capacity measurement

Measured through the GitHub search API on 2026-08-26: 3,575 open pull
requests, 1,880 opened in the last 30 days against 74 merged and 68
closed unmerged, no commit to `main` since 2026-08-17, and the oldest
open entry filed 2025-12-03.

Arrivals outrun resolutions about thirteen to one. The growth is
observable at close range, which is what makes it more than a snapshot:
the same query two days earlier returned 3,437 open, so the backlog
gained 138 in 48 hours while the 30-day merge count fell from 96 to 74.
A pull request filed today waits roughly four years on the monthly rate,
and the current rate is zero.

The `🤖🤖🤖` agent fast track `CONTRIBUTING.md` offers is the part worth
keeping. 1,666 of the 3,575 open pull requests carry it, so it marks 47%
of the queue and confers no priority. A signal any submitter can apply
to their own submission stops being a signal, and the failure is
structural rather than anyone abusing it. Any unpriced marker aboard
offers agents ends up the same way.

### 2. What that says about aboard, which is less than it first appears

Not a present problem: 25 claims, no inbound volume, and the operator's
read that this state may never arrive is reasonable for a research
prototype. `research/review-capacity.md` says so in its own second
paragraph rather than burying the caveat.

What it does establish is that the gate carries a property nobody has
costed. `CONTRIBUTING.md` argues for it entirely on Sybil-resistance
grounds, and that argument is sound and undisputed here. Sybil
resistance and throughput are independent axes, though, and
`awesome-mcp-servers` is a design whose Sybil defence held perfectly
while its throughput went to zero. Nothing hostile got in. Nothing got
in.

The trigger is success rather than attack, which is the uncomfortable
part: the load that breaks a human gate is indistinguishable from the
outcome chunk 8 is written to produce. The note sketches four directions
(tiered review, per-token throughput budgets, a published SLA with
visible queue depth, an accepted-but-unreviewed tier) and evaluates none
of them, because costing the risk was the task and building for it was
not.

### 3. The second half of the note, and its failure condition

The Glama incident from session 69 is the evidence for a different
product. Glama produced a status with three candidate causes, all three
wrong. What the situation needed was a root cause, a reproduction and a
fix. Every automated check in this ecosystem produces the first kind of
output.

The note is careful about what is already occupied, since the listing
layer is thoroughly served and a fourth list has no reason to exist. The
gap it identifies is semantic review: whether a tool description matches
its schema, whether the server does what its README says, whether the
tool surface is prompt-injection-shaped, whether advertised
authorization actually holds. Those are questions an agent can answer
cheaply, whose answers change over time, and which no liveness probe
touches.

Two things keep it honest. It states a failure condition in advance: if
twenty servers yield no finding a liveness check would have missed, the
gap does not exist, and that is a useful result. And it names the two
constraints as constraints rather than footnotes, prompt injection
(reviewing means running strangers' code and letting its output reach a
model's context, so a review agent that can be talked into a favourable
finding is worse than none) and scope against an unshipped launch post.

### 5. The Glama badge did not clear, and the reason is not the origin

Session 69 fixed a real origin-guard defect and this session claimed it
would clear the badge. It did not. Glama re-tested 2026-08-26 17:40,
after the deploy, and still reports unhealthy.

Re-probed rather than assumed. The endpoint is correct on every
black-box measure: 200 for `POST initialize` with `Origin:
https://glama.ai` set, 204 for the preflight, all nine tools on
`tools/list`, clean negotiation across four requested protocol versions
including an unknown one, and 403 still returned for a malformed
`Origin`. Rate limiting is not involved: `PROPOSAL_LIMITER` is keyed per
credential on the write path, so an anonymous read never touches it.

`wrangler tail` on the production Worker found what black-box probing
could not. Fourteen requests reached `/mcp` in four minutes: twelve
`GET`, one `HEAD`, all thirteen answered 405, and exactly one `POST`
caller (`SentinelOracle/0.1`) answered 200 and 202. None of the thirteen
sent an `Origin` header at all, which is precisely why session 69's fix
did not move them. They never reach that check.

Whether any of them is Glama is unproven, because none identifies
itself and the browser-shaped user agents are generic. The entry in
`knowledge/issues.md` says that rather than claiming a root cause a
second time. What is established independently of Glama is the traffic
shape: `GET` is how automated clients touch this endpoint, and every one
of them sees a failure status.

The 405 is deliberate and spec-permitted for a server with no SSE
stream. So this is a reachability question rather than a defect, and the
decision it opens (serve SSE on `GET`, which is spec-correct and adds
streaming surface to a deliberately stateless Worker) was scoped out of
this session rather than taken in passing.

## Decisions worth remembering

- **A checklist item that cannot be satisfied is a record that lies.**
  "The awesome-mcp-servers PR is merged" was unreachable at 74 merges a
  month against a 3,575 backlog. Changing it to "filed" is the same
  class of fix as session 70's plan-index sweep.
- **Measure the queue, do not eyeball it.** 3.4k open reads as a
  backlog. 1,880 arrivals against 74 merges in the same month reads as
  a closed system, and only the second one tells you the wait is
  unbounded.
- **An unpriced priority marker converges to noise.** The `🤖🤖🤖` fast
  track was a good-faith accommodation for agents and now marks 47% of
  the queue. Directly relevant to anything aboard offers agents later.
- **Black-box probing has a floor, and the tail is under it.** Every
  externally constructible probe passed while thirteen of fourteen real
  requests were failing. The failing calls used a method nobody thought
  to test, because the working path was the one being defended.
- **Say hypothesis when it is a hypothesis.** Session 69's origin fix
  was announced as clearing the badge and did not. The `GET` finding is
  stronger evidence and still unproven as the cause, so it is recorded
  as such.
