## Context

A cleanup slice after the write path closed out: turn CI's lint step from
advisory into a hard gate. It had run `continue-on-error: true` since session 15
because of 5 pre-existing `eslint-plugin-react-hooks` (React Compiler-preview)
errors. This session fixed them and flipped the gate. Also deleted the stale
`chore/wire-custom-domain` local branch (PR #32 long merged).

## What happened

### Cleared the 5 lint errors

The plugin (`eslint-plugin-react-hooks@7`, via `eslint-config-next`) ships the
React Compiler rules as errors, but the compiler is not enabled here (no
`reactCompiler` in `next.config`), so they fired on working, intentional code.

- **`react-hooks/refs` ×3 in `ClaimGraphRF.tsx`.** The latest-value
  `nodesRef`/`edgesRef` writes moved out of render into an effect (they are read
  only from event handlers that run after commit, so a one-commit lag is
  immaterial). The new-node modal's centring position, previously computed by
  reading `wrapperRef.current.getBoundingClientRect()` in a render-time IIFE, is
  now a `getDefaultPosition()` callback the modal invokes at **save** time —
  `defaultPosition` was only ever read in the modal's `save()` handler, so this
  is behaviour-preserving and also drops a per-render layout reflow.
- **`react-hooks/preserve-manual-memoization` and `react-hooks/set-state-in-effect`.**
  Compiler-preview rules with no runtime meaning when the compiler is off, both
  flagging intentional patterns (seed initial RF state once; hydration-safe
  client theme init). Suppressed at the site with a justification comment.

Result: `npm run lint` is **0 errors** (15 warnings, which do not fail eslint).

### Flipped the gate

Removed `continue-on-error: true` from the CI `Lint` step and rewrote its
comment. Errors now block; the pre-existing warnings do not (eslint exits
non-zero only on errors). Closed the tracking entry in `knowledge/issues.md`.

## Decisions worth remembering

- **Fix what has a clean fix; suppress the compiler-preview noise with a
  reason.** Two of the five were genuine render-phase hazards with idiomatic
  fixes; the other two are React Compiler rules that a compiler-off project
  gains nothing from enforcing. Refactoring a 1000-line interactive graph to
  satisfy preview rules is the wrong risk under a lint task.
- **A getter beats a value when the read must happen at event time.** Passing
  `getDefaultPosition()` instead of a pre-read `defaultPosition` moved a layout
  read out of render entirely — the correct shape, not a workaround.
