## What happened

### 1. The plan's architecture was impossible, and the plan didn't know it

The plan specifies `POST /api/proposals` as a **Next.js API route**. It cannot
be. Session 14 migrated aboard to static export, and Next's own docs
(`node_modules/next/dist/docs/01-app/02-guides/static-exports.md`) are explicit:

> Route Handlers will render a static response... **Only the `GET` HTTP verb is
> supported.**

with "Route Handlers that rely on `Request`" listed under Unsupported Features,
alongside Server Actions, cookies, and headers. The plan predates the migration
and was never reconciled with it. Checking the docs before writing code — as
`AGENTS.md` demands — is the only reason this was caught before building the
wrong thing.

**The endpoint lives in the Cloudflare Worker instead** (`worker/index.ts`). The
site already deploys as a Worker with a static-assets binding, so this is the
same origin and the same deploy. Every property the plan actually wanted
survives: the GitHub credential never leaves the server, and the canonical Zod
schemas remain the single source of validation truth. Static export stays intact.
Every path other than `/api/proposals` falls straight through to the assets.

### 2. `propose_claim`, end to end (`fdf8021`)

Agent → MCP `propose_claim` → `POST /api/proposals` → Zod validation →
provenance stamped from the token → branch + commit + **pull request**. Never a
merge.

The Worker is a deliberately thin shell (HTTP, token lookup, GitHub calls). The
decisions that matter are pure and unit-tested in `src/lib`:

- **`proposals.ts`** — what a valid proposal is; how a domain's id prefix is
  inferred; how an id is minted.
- **`data/serialize.ts`** — the claim file the loader must be able to read back.

**Id minting reads the convention off the data, not a registry.** Ids are
`<domainPrefix><kindLetter><n>` — `S1`/`M1`/`L1`, `IS1`/`IM1`/`IL1`,
`ECS1`/`ECM1`/`ECL1`. The prefix is *not* derivable from the domain's name (`EC`
for epistack_cases is initials; `I` for inequality is not), so it is read off the
domain's existing claims. A registry would drift; the data cannot.

It **refuses rather than guesses**: a domain with no claims yet gets an error,
because inventing a prefix would silently fork that domain's namespace and
nothing downstream would notice.

### 3. A round-trip test caught a real bug before it shipped

The serializer's first version wrote `createdAt: 2026-07-14T12:00:00.000Z`
unquoted. YAML resolves that to its **timestamp** type, so the loader's parser
(gray-matter → js-yaml) hands it back as a `Date`, and the schema types it as a
string. **The file the write path committed would not have parsed back.** Every
hand-authored file in `data/` quotes its timestamps; that is why.

The round-trip test (serialize → gray-matter → `Claim.parse` → deep-equal) failed
on the first run and is the only reason this was caught. The whole product of a
write path is a file the loader can read.

### 4. Attribution grew provenance (`884c83b`)

Plan step 7, which the plan says to do now rather than later. `AgentAttribution`
gains optional `operator` (the accountable human or org behind the token) and
`agentId` (stable id for the agent *configuration*). Both are **stamped
server-side and never read from the payload** — an attribution a caller can
assert about itself carries no information.

Per CLAUDE.md the schema moved with the serializer, in one commit: `types.ts`,
`jsonld.ts`, `public/schema/v0.json` (its `Author` is
`additionalProperties: false`, so the new keys had to be declared or valid output
would have started failing validation), and `research/schema.md`.

### 5. CI grew to cover the new surface

The write path spans three packages, and a change to `src/lib/types.ts` can break
the Worker or the MCP server without the app's own type-check noticing. CI now
bundles the Worker (`wrangler deploy --dry-run`) and type-checks the MCP server.

## Decisions worth remembering

- **Check the plan against the code before following the plan.** This one
  confidently specified an architecture the deployment made impossible six weeks
  earlier. A plan is a hypothesis, not an instruction.
- **The caller supplies content, and nothing else.** Not identity, not ids, not
  timestamps. This is the whole security posture in one line.
- **Refuse rather than guess.** A domain with no claims gets an error instead of
  an invented id prefix. Silent namespace forks are unrecoverable; an error is a
  five-second fix.
- **The Worker holds the logic nowhere.** Everything that can be decided purely
  is decided in `src/lib`, where vitest can reach it. The Worker does HTTP.
